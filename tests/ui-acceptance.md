# KaneoPilot 桌面人工验收清单

依据 `docs/ui-spec.md`（冻结）逐条验收。每项完成打勾；截图点标注 📷。
验收基线：macOS 14+，浅色/深色各一遍，默认 1180×760 与最小 900×600 两种窗口尺寸。

## 0. 启动与窗口

- [ ] 应用启动后窗口标题为 `Kaneo 调度台`
- [ ] 默认窗口尺寸 1180×760；可缩至最小 900×600，更小被拒绝 📷（两尺寸各一张）
- [ ] 侧栏固定四节：任务 / 待处理 / 运行记录 / 设置，图标为 `list.bullet.rectangle`、`tray.full`、`clock.arrow.circlepath`、`gearshape`
- [ ] 侧栏可收起；内容区为「列表 + 详情」双栏
- [ ] 窗口收窄到 SplitView 折叠时，详情压栈为单独页面，可系统返回 📷
- [ ] 工具栏含刷新按钮与全局暂停/恢复按钮；命令不可用时显示原因提示
- [ ] 关闭窗口再打开：队列/状态从核心重新读取（窗口关闭不取消请求）

## 1. 浅色 / 深色外观

- [ ] 系统浅色模式下全部视图无硬编码颜色痕迹 📷
- [ ] 系统深色模式下全部视图对比正常、无白色残块 📷
- [ ] 状态永远「图标 + 文字」双编码，不依赖颜色单独传达
- [ ] 正文 13pt；详情标题 18pt semibold；辅助/时间戳 11pt secondary
- [ ] 间距只出现 8/12/16 三档；列表行高 ≥40pt；分隔为系统 Divider

## 2. 任务视图（主列表 + 详情）

- [ ] 列表行含：项目徽标（11pt）、标题（单行截断）、状态文字+图标、最近进展（11pt secondary 单行）
- [ ] 阻塞原因以 11pt 红色显示（needs_user 任务）
- [ ] 有 queued 请求的行显示预计领取时间（`HH:mm` 或 `约 x 分钟后`）
- [ ] 排序：需人工/失联置顶 → 已排队 → 执行中 → 其余按更新时间倒序
- [ ] 搜索框按标题/项目过滤；阶段筛选菜单可用
- [ ] 长中文标题（40+ 字）单行截断、不撑破布局 📷（用例：粘贴 60 字中文标题任务）
- [ ] 详情六区块齐全：计划 / 执行 / Kaneo / Review / 尝试与时间线 / 阻塞
- [ ] 「打开计划文件」可打开 plan 文件；「在 Finder 显示」可用
- [ ] session_id/session_marker 可复制；「打开 Kaneo 任务」打开正确 URL
- [ ] 底栏操作按钮与 `get-task` 返回的 `allowed_actions` 一致（无多余按钮）
- [ ] 按钮文案正确：`安排下一步` 按 kind 变为 安排派发/安排规划/安排检查/安排评审
- [ ] send_state=unknown 任务展示原尝试证据块，且只有 恢复原任务/接受可能重复，重新派发/登记已发出，**不**显示普通重试 📷
- [ ] 危险操作（接受可能重复、登记完成、释放失联请求、恢复原任务）弹确认对话框写明后果 📷
- [ ] `重新校验` 始终可用，离线时给出明确结果反馈

## 3. 待处理视图

- [ ] 聚合展示：queued/claimed/lost 请求 + needs_user 任务 + 最近失败
- [ ] 行显示 kind/stage 图标+文字、任务标题、状态（已排队 X 分钟/进行中/失联红）、claimed_by、等待时长
- [ ] queued 行可调整顺序（优先级菜单）
- [ ] lost 行提供「释放失联请求」
- [ ] needs_user 行可跳转任务详情
- [ ] 空态显示 `暂无待处理项` + 说明文字 📷

## 4. 运行记录视图

- [ ] 事件时间线倒序，行含时间、事件 kind（中文映射）、任务标题、摘要
- [ ] 可按任务过滤；搜索框过滤文本可用
- [ ] 空态文案正确 📷

## 5. 设置视图

- [ ] doctor 结果逐项列出（名称 + ok 图标 + detail），`重新检查` 可用
- [ ] `包含 Kaneo 连通性` 勾选后执行 online 检查（kaneo_ping 不再 skipped）
- [ ] 全局暂停开关 + 各 stage 开关，与 `overview.paused` 一致
- [ ] 领取间隔等 settings 值只读展示
- [ ] Plan 根/仓库根/DB 路径/核心路径只读展示 + 「打开所在目录」
- [ ] 已迁移时显示迁移时间与备份路径

## 6. 反馈与状态（全部必须验证）📷 每态一张

- [ ] 加载中：列表中央 ProgressView + `正在读取…`
- [ ] 命令执行中按钮 disabled + spinner
- [ ] 空队列：`暂无任务` + 说明 + `刷新` 按钮
- [ ] 核心不可达（kill 核心/错误 KANPILOT_CORE）：顶部横幅 `无法连接调度核心：<原因>` + `重试`；旧数据保留并标 `可能已过期`
- [ ] 读取失败：错误横幅 + `重试`，旧数据不清空
- [ ] 操作成功：工具栏旁 checkmark 或轻量 toast，并立即刷新数据
- [ ] 操作失败：alert/横幅显示核心返回的 `error` 原文（如 `已有活动派发请求`）
- [ ] 禁用按钮置灰 + tooltip/原因标签
- [ ] 连续点击 `安排下一步`：核心幂等返回同一请求，UI 不重复派发 📷

## 7. 键盘 / 焦点 / 无障碍

- [ ] 列表 ↑↓ 选择、回车进入详情、⌘R 刷新
- [ ] 所有可点控件 focus ring 可见；Tab 顺序合理
- [ ] 状态图标均有中文 accessibilityLabel（如「需人工」「执行端失联」）
- [ ] 列表行 VoiceOver 读出完整摘要（项目/标题/状态/进展一句话）
- [ ] VoiceOver 可完成：选任务 → 进详情 → 触发「安排下一步」全流程
- [ ] 按钮均有文字标题或 label；状态不仅靠颜色区分

## 8. 端到端验收（automation-contract §5 检查点）

- [ ] 桌面 `安排下一步` → 任务显示 `已排队`；执行端领取+心跳 → 显示 `派发中`/`执行中`
- [ ] 发送不明任务呈现证据块与三个专用按钮；任一决议后生成对应请求
- [ ] running 任务迁移后由 monitor 请求接续观察，无旧锁残留
- [ ] 暂停自动推进后执行端不再领取；恢复后继续
- [ ] 主线程无阻塞：核心调用期间 UI 可滚动/缩放（长时间 fake 延迟下验证）
