# KaneoPilot 桌面界面规格 v1（冻结）

定位：本机原生工具型工作台。不做人格化设计、不做营销首页、不用大卡片/装饰图。系统浅/深色自适应。

父任务收尾（2026-10-19）：继承现有详情概览、评审页的 `DetailSection`、状态徽标与底部主按钮，不改全局布局/token。消费 protocol §5.27.18 的 `parent_closeout`；「收尾校验」置于旧修复会话位置，显示二级任务完成数、结果摘要、缺项及未核验体验说明，任务层级继续保留直达子任务。ready 为「待收尾校验」且主按钮「校验并完成」；执行期间沿用全局 busy 禁止重复点击；blocked 为「收尾校验受阻」，unknown 为「完成同步待确认」并说明不会重复提交；completed 为「已完成」并展示复用检查点。旧 changes_requested 仅作为历史评审，不继续占用顶部待修复横幅或提供启动旧修复。看板与紧凑列表共用核心状态，ready 留评审列，blocked/unknown 属阻塞，不属于失败。人工、真机或真实服务体验未核验时显示该事实，不标成已验收。原生核验覆盖候选、缺项与完成态，保留窄窗换行和内容滚动。

构建发布（2026-10-19）：遵循 [release-contract.md](release-contract.md)；在既有项目「自动处理」表单加入发布开关及预发布/正式渠道，工作流、版本种子、必需包及 job 名折叠展示。首次开启与切正式版确认具体项目、渠道及 Actions 配额影响。详情「交付」内嵌发布状态、版本、Actions/Release 与包下载链接，unsigned iOS 明示限制；看板只加一行发布摘要。ready 经 prepare 后展示目标 SHA/关联任务并确认；历史 done 为显式「补发版本」，保持已完成；unknown 仅核对，不提供再次发送。页面消费核心 DTO 和动作，不自行判断发布成功。

## 1. 技术形态

- SwiftUI + AppKit 互操作最小化；macOS 14+ SDK；单窗口 `WindowGroup`。
- 数据全部经 protocol.md CLI 获取/变更（`Process` 调 `kanpilot`，JSON 进出）；不直接读写 SQLite，不内嵌调度逻辑。
- 命令调用放后台线程/actor，主线程零阻塞；UI 状态用 `@MainActor` view-model。
- 开发期数据源可用 `KANPILOT_CORE` 环境变量指向核心脚本；缺省找 `../core/kanpilot`（repo 布局）与应用内 `Resources/core/`。

## 2. 窗口与导航

- 默认窗口 1180×760，最小 900×600；标题 `Kaneo 调度台`。
- 顶层 `NavigationSplitView`：侧栏固定七节 —— **任务**、**执行会话**、**待处理**、**归档**、**回收站**、**运行记录**、**设置**（SF Symbols：`list.bullet.rectangle`、`bubble.left.and.bubble.right`、`tray.full`、`archivebox`、`trash`、`clock.arrow.circlepath`、`gearshape`）。
- **规划面板**（§4.7）：从「任务」区工具栏按钮 `规划待办…`（SF Symbol `doc.text.magnifyingglass`）与待处理/请求详情中的 `准备规划` 动作打开；独立窗口/大 sheet，约 760×600。
- 内容区为「列表 + 详情」双栏；宽度不足（SplitView 折叠）时详情压栈为单独页面（`navigationStack` push），系统返回。
- 侧栏可选收起；工具栏分两组，每个控件都有可见文字。**全局组**：自动推进按钮（运行中为 `暂停自动推进`，`pause.fill`；已暂停为橙色 `已暂停 · 恢复自动推进`，`play.fill`；全局态，提示写明只阻止新领取、已在执行的不受影响）与刷新（`刷新 HH:mm`，`arrow.clockwise`，⌘R；无刷新记录时仅 `刷新`）。状态槽仅在命令进行中、横幅或未找到核心时显示（命令不可用原因提示）。**任务组**见 §4.13。

## 3. 字体、颜色、度量

- 工具栏命令进行中的状态提示固定显示图标及「正在执行：动作」文字，按内容保留宽度，不随工具栏的自动 Label 样式折叠为孤立图标；胶囊内部水平留白 12pt、垂直留白 8pt，图文不得贴边或被边界裁切；命令结束后移除状态提示。

- 正文 13pt（`Font.system(size: 13)`）；区段/详情标题 18pt semibold；辅助/时间戳/次要信息 11pt（secondary 色）。
- 颜色只用系统语义色：`Color.primary/.secondary`、`Color(nsColor: .separatorColor)`、`Color(nsColor: .controlBackgroundColor)`、`Color(nsColor: .windowBackgroundColor)`；状态色用系统 `.green/.orange/.red/.blue/.gray` 且**必配文字**，不单靠颜色。
- 间距只用 8 / 12 / 16pt 三档；列表行高 ≥40pt；分隔用系统 `Divider`；圆角/阴影默认系统值，不自定义卡片容器。
- 图标只用 SF Symbols（见 §5 映射）。

## 4. 四个视图

### 4.1 任务（主列表 + 详情）

- **阻塞与失败分开呈现（2026-10-18）**：保留六个流程列与核心 board_column。第六列标题改为中性「阻塞 / 失败」，列内固定为橙色「阻塞」、红色「失败」两个独立分组，分别计数；判定只用 exception.severity，failed 才属于失败，其余异常均为阻塞。两组使用三角提示／叉号图标及文字双编码；原因颜色跟随分组。紧凑列表使用相同分组。详情状态牌优先展示核心异常的阻塞/失败语义，评审通过待合并明确显示「评审通过 · 待合并」，不继续称正在评审、不提前完成任务。
- **原始任务与二级任务（2026-10-18）**：看板与紧凑列表消费 task_relations，只展示直接关联。原始任务标「原始任务」，有子任务时附二级任务数；子任务标「二级任务 · 评审修复」，左侧缩进 12pt 并使用细引导线。同一流程列／异常分组内，来源原卡在前、关联子卡随后；来源在其他列或被筛选时，保留紧凑的「原始任务：名称」上下文行与来源入口，不计为当前列任务、不重复参与批量选择与键盘卡片导航。子任务保留独立的状态和所在列，不因父任务受阻而搬列；搜索子任务时仍保留来源上下文。来源不可用时显示不可用与保留 ID，不伪造名称、不提供可执行入口。
- 层级分组的视图身份包含所在流程列及异常分组；同一来源的子任务跨列显示或搜索过滤后，必须仍绑定各自任务内容，不能复用其他列的来源分组内容。
- 详情概览在 Kaneo 关联之前增加「任务层级」，显示当前是原始任务或二级任务，以及来源／关联二级任务的标题、状态和直达入口；评审页同步显示该区，原有「修复任务」字段改称「本轮新增修复任务」，避免误以为无来源。关联导航复用同一详情容器，并提供「返回上一级」。关联只是导航，不触发规划、执行、Review 或远端写；保留五段导航、字号、间距、布局风格和原任务数据。
- 评审通过且进入交付阶段时，概览下一步说明当前待合并／待交付；底栏仅在核心允许时推荐「重新校验」，不再推荐重复安排评审。其余核心允许动作保留在更多操作中。
- **项目自动合并（2026-10-18）**：项目与仓库设置的「自动处理」中，紧接「自动确认计划」增加「自动合并 PR」开关，默认关闭，说明开启后覆盖当前与后续待交付任务、检查通过且无冲突时采用 merge commit 合并、不调用模型。开启保存使用系统确认弹窗，列出项目和影响，确认才保存；取消保留草稿、不写设置。独立于新任务自动接收，保留已有布局、字号、间距和其余设置。任务卡和概览展示核心 delivery.auto_merge.reason；阻塞原因橙色、未知结果明确不会重复提交；合并后、任务尚未完成时显示等待完成同步；任务已完成则显示“PR 已合并，任务已完成”，不再用历史回执遮盖最终状态。

- 列表行：项目名（11pt 徽标文本）、标题（13pt，单行截断）、当前阶段/状态（文字+图标）、最近进展（11pt secondary 单行）、阻塞原因（有则 11pt 红）、预计领取时间（有 queued 请求则显示 `HH:mm` 或 `约 x 分钟后`）。
- 排序：需人工/失联置顶 → 已排队（按 priority+创建时间）→ 执行中 → 其余按 updated_at 倒序；项目可分组标题。
- 过滤：工具栏搜索框（标题/项目匹配）+ 阶段筛选菜单（标签显示当前值 `阶段：全部` / `阶段：<列名>`；有筛选时使用强调色）。
- 详情（选中任务，T4 五段式）：详情容器保持 sheet 尺寸、标题/状态与关闭入口；顶部分段控件 `概览 / 计划 / 执行 / 评审 / 记录` 五段，每页独立滚动、切换不丢当前任务。键盘左右键切换分段，焦点与 VoiceOver 读出页名。
  1. **概览**：按「需要你处理（阻塞横幅、阻塞证据、待答问题、待评审项，仅在出现时）→ 状态与下一步（下一步说明；最后更新，以及仅有值时的自动推进已暂停、保存状态）→ 进展（阶段步进只高亮；已结束的问答一行摘要；内联直达链接）→ Kaneo 关联（kaneo_status/最后核验时间/`打开 Kaneo 任务`）→ 交付／自动处理 → 技术详情（折叠）」排列。阻塞证据保留 needs_user/失联时的 failure_code/failure_reason/证据摘要，并保留允许操作摘要。概览不重复头部的状态与阶段文字，不另设「当前状态」行；「生命周期阶段」只在核心未给出 phase 时显示。
  2. **计划**：按 §4.8 计划阅读页展示已发布计划。
  3. **执行**：父页标题独占首行，最多两行，可选择与获取完整文字；第二行状态、五段导航和关闭。共用 `SessionReaderView`；轮次字段（run_id/session_id/session_title/session_marker/worktree_path）统一在阅读器“会话详情”按需查看，不在父页另铺技术横条；无会话显示空态。
  4. **评审**：结论/报告路径/fix_task_id/`打开报告`；无评审数据显示空态。
  5. **记录**：两个并列区段（不嵌套卡片）——「尝试记录」（时间、阶段、结果、说明，结果列图标+文字，行高 ≥40pt，说明按内容自然撑高不截断单行）与「事件时间线」（时间、类型、摘要三列，行高 ≥40pt，类型列固定宽度且不折断 `round_observe` 等标识）。单个外层滚动；点击一行展开完整 note/evidence 或结构化 `detail` 原文（可复制）；默认显示核心 `EventItem.summary` 中文一句话；未知 kind 保留原值且可完整查看。此页只称「最近记录」（数据源 `get-task.attempts` + `list-events(limit:200)`），不冒充全史。
  没有对应数据时显示清晰空态文案，不显示空白表。
  五段导航始终固定在浮层顶部，切换分段不改变浮层的有效尺寸；内容区填满导航以下的可用高度且只滚动一次。顶栏在五段间结构与高度一致：第一行为项目标签与任务标题（最多两行，可选择与获取完整文字），第二行为状态、五段导航与关闭；切换分段时顶栏高度与导航位置不变。计划页与执行页一样不重复标题（见 §4.8）。
- **待办列直达计划页（T1）**：待办（`board_column=todo`）列卡片的主入口直接打开同一详情容器的**计划页**（非概览）；其他列仍默认打开概览。计划页可切回概览/其他页；「准备/重新规划」仍跳转既有规划面板。
 - 计划页头部按 §4.8 展示 `plan_kind`、生成时间与 plan_sha256 前 12 位（可复制）；任务标题与 `待确认执行` 状态只由父详情顶栏显示一处（同执行页），父详情隐藏顶栏时计划页补回（标题 18pt，单独首行、最多两行）；模式分段与打开/定位按钮置于独立操作行，不与元数据争宽。
- 详情底栏操作区：按钮由 `get-task` 返回的 `allowed_actions` 渲染，映射：
  - `enqueue` → 按 `get-task` 的 `enqueue_kind` 显示：`plan`→`安排规划`、`dispatch`→`安排派发`、`monitor`→`安排检查`、`review`→`安排评审`；`enqueue_kind` 缺省或未知时回退 `安排下一步`。kind 只由核心给出，界面不据 status 推导。存在活动请求时核心不返回 `enqueue`，界面不自行补出。
  - `retry` → `重试派发`（仅 send_state=not_sent 等明确未发送）
  - `restore` → `恢复原任务`（unknown）
  - `accept_duplicate` → `接受可能重复，重新派发`（unknown；需二次确认对话框写明风险）
  - `mark_sent` → `登记已发出`（unknown；确认对话框）
  - `replan` → `重新规划`
  - `release_lost` → `释放失联请求`（失联时）
  - `mark_done` → `登记完成`（确认对话框）
  - `dismiss` → `清除阻塞标记`
  - `recheck` → `重新校验`（始终可用，off 时明确结果反馈）
  - `set-priority` → 对 queued 请求提供 `上移/下移` 或优先级菜单
  - `set-paused` → `暂停自动推进`（运行中）/`已暂停 · 恢复自动推进`（已暂停）（全局，工具栏+设置双入口）
  - `prepare_plan` → `准备规划`（打开规划面板定位到该任务；v2 起 `安排规划` 不再直接排队）
  - `confirm_dispatch` → `确认并安排执行`（任务 `plan_execution_hold` 为真时替代普通「安排派发」；点击后核心以 `confirm_plan:true`+`expected_plan_sha256` 同事务复核，失败展示 `conflict` 原文）
- 任务 `plan_execution_hold=true`（publish-plan 成功后）：状态行显示 `待确认执行`（图标+文字），详情「计划」区块给哈希前缀；未确认前不显示普通 `安排派发`。
- 发送不明（send_state=unknown）必须展示原尝试证据块（attempt evidence），并在按钮区只给 restore/accept_duplicate/mark_sent，**不**显示普通重试。

### 4.2 待处理

- 聚合：活动请求（queued/claimed/lost）+ needs_user 任务 + 最近失败请求。
- 行：请求 kind/stage 图标+文字、任务标题、状态（已排队 X 分钟/进行中/失联 红）、claimed_by、预计/已等待时长。
- 支持：对 queued 行 `调整顺序`（优先级）、`取消排队`（若协议提供 cancel——当前版本没有则不给该按钮）；对 lost 行 `释放失联请求`；对 needs_user 行跳转任务详情。
- **请求详情页（v2，protocol §5.21.1）**：点击请求行进入详情（`get-request`）。分区块展示：请求字段（kind/stage/status/priority/not_before/claimed_by/租约时间）、关联任务摘要（`task` 为 null 显示「无关联任务」）、`attention_state` 徽标（`actionable` 需处理/`historical` 历史/`informational` 记录，图标+文字）、`attempts` 列表（每次尝试的时间/result/note/failure/send_state/evidence 可展开）、`log_path` 存在时给 `打开日志`。
- 详情底栏按 `allowed_actions` 渲染按钮（UI 只渲染不自判）：`view`→查看关联、`set-priority`→调整顺序、`release_lost`→释放失联请求、`retry`→重试、`replan`→重新规划、`prepare_plan`→准备规划（打开规划面板）、`fetch_todos`→重新获取 To Do（打开规划面板）。`blocked_reason` 非空时在按钮区下方以 11pt secondary 展示。
- `read_only=true` 详情（purged 关联/终态无动作）：顶部固定 `只读` 徽标 + 原因，按钮区为空。
- 空态：`暂无待处理项` + 说明文字。

### 4.3 运行记录

- 时间线列表（`list-events`，`id` 倒序）；行显示：时间、事件 kind（中文映射）、`task_title`、`project_name`（11pt 徽标）、`stage`、`result`、`summary`（中文一句话，11pt secondary 单行截断）。
- **游标翻页**：底部 `加载更多`（有 `next_before_id` 时可用，点击追加下一页；加载中转 spinner）；翻页期间新事件不影响已翻页顺序。`limit` 固定 100。
- **过滤与搜索**：工具栏搜索框 + `stage`/`result` 筛选菜单；搜索与筛选由核心在**全部历史**上执行（不只当前页），输入防抖后重新查询并清空已翻页游标。
- 行点击展开详情：原始 `detail` JSON、完整 `task_id`/`request_id`、actor（均可复制）；无 `task_id` 的事件同样可展开。
- 已 purged 任务的历史事件照常显示；`task_title` 用核心回填值（含 `未保留标题 · <短id>` 占位），UI 不自行猜测。
- 空态文案。

### 4.4 设置

- 环境诊断：`doctor` 结果列表（每项 名称+ok 图标+detail；`重新检查` 按钮；online 勾选 `包含 Kaneo 连通性`）。
- 自动推进：全局暂停开关 + 各 stage 开关（读取 overview.paused）；`领取间隔`等只读展示 settings 值。
- 路径只读展示：Plan 根、仓库根、DB 路径、核心路径；`打开所在目录` 按钮。
- 迁移状态：`settings.migration` 存在则显示导入时间与备份路径。
- **PI 执行配置（v1.6，protocol §5.17）**：独立分节，四个选择器（provider / 模型 / 思考等级 / agent.md 预设）+ 环境检查列表：
  - 选项与能力来自 `exec-capabilities`（加载中显示进度；失败保留已有内容 + `重试`）。
  - 思考等级选项**只列当前模型支持的值**；预设只列 `agents_dir` 有效项（`<name>.md`）；模型/provider 不在能力列表时禁用保存并写明原因。
  - 保存经 `set-exec-config`，成功 toast「已保存执行配置（仅影响新轮次）」；失败展示核心 `error` 原文并保留原值。

- **滚动与实时跟随**：打开轮次（首次消息落地）直接定位到**最新消息**（底部），不做「停在第一条 prompt」的中间态；每 2s 增量轮询到新内容且仍贴底时自动跟到最新。用户主动上滚离开底部（距底 ≥48pt）→ **不被拉回**，出现「有新内容」按钮，点击回到最新并恢复跟随；切换轮次重置为贴底跟随。判底依据**真实滚动几何**：滚动了多少由原生滚动视图的边界变化实测（SwiftUI 的 GeometryReader 偏好只在内容重新布局时回传，macOS 上用户滚动拿不到新位置，不得据其判底），内容高度仍以 LazyVStack 布局后回传为准；自动滚动的二次纠正期间不得把中间态判成「离开底部」而产生假「有新内容」；折叠/展开与搜索过滤引起的重排中间态不得判成「贴底」，即逐条展开/收起只改变该条高度，不把上滚中的视口拉回底部。
 - **无变化轮询不重排（T1）**：轮询到无新消息且会话状态未变时，不得重新发布消息数组、不得安排自动滚动；有新消息或修订时只处理改变的行，仍按 `seq` 排序，折叠/展开状态跟随消息 `id`（修订替换沿用原状态）。折叠的长正文只排版可见预览，完整原文仍可复制；搜索命中时仍能看到命中内容。上滚停止跟随、回底部、「有新内容」按钮与切轮次重置贴底的语义不变。
- 加载/失败/重试/禁用原因/焦点与 VoiceOver 沿用 §6/§7 既有规格；度量不变（18/13/11pt、8/12/16、行高 ≥40、1180×760 / 900×600）。

## 关键设计决策

### 2. 展示准备只随消息变化，不随每帧变化

保留 `SessionMessage` 原始字段。新增会话专用 `SessionMessagePresentation.swift`，准备结果按 `(run_id, id, revision)` 归属当前阅读器；等价重发不重做，切轮次释放旧会话结果。准备正文、判长、预览、可读工具字段及搜索素材在后台进行，主线程只应用属于当前 generation 的结果；不引入全局缓存、磁盘缓存或更换状态框架。

预览采用双上限：最多四个可见行、最多 512 个 Unicode 字符；遇到第五个换行或达到字符预算即停止取预览，追加省略标记。判长沿现有“超过四行或 320 字符”，用有界扫描判断，不在行 body 中每次 `text.count/split` 整篇。单行 JSON 同样受限。可访问性名称只含角色、时间、状态与有界摘要；全文在阅读浮层可读取，不每次将巨大原文拼入行的 AX label。

元数据栏与消息区使用独立、稳定的观察输入。`last_checked_at` 更新只影响时间信息，不触发正文解析、搜索全量计算或高亮准备；following/hasNewContent 只在值变化时发布。复用已有 `applyMessages` 的等价比较与折叠迁移，列表仍用懒加载。

### 3. 工具展示只识别已知结构，原文保持完整

优先使用结构化 `SessionTool.name/input/output/exitCode`。对于截图这类包装，在展示准备阶段识别 `content:[{type:"text"或text字段}]`，取文本内容；该文本本身是 JSON 且含 `command/commandShellId/stdout/stderr/exitCode/exit_code` 时，再解码一层，最多两层。不做递归字符串替换，不把任意字面量 `\n` 改成换行，不执行内容。

自动解码预算为单条候选原文 ≤256 KiB；超限或未知结构显示“原始工具结果 · 大小”与有界预览，提供全文原文入口。解析失败不是任务失败，也不能伪造输出或丢掉原文。多 text 项保持原顺序；存在非 text 项时保留原文入口和“另有原始内容”提示。只对明确提供的整数退出码显示“退出码 0”或“退出码 N”；缺失时显示“状态未提供”，不能由 stderr 为空推断成功。

折叠状态显示工具名/命令摘要、状态文字和输出前四行。展开后按“输入 / 标准输出 / 标准错误”分区，不再同时重复打印包装 JSON、正文和相同 output。输入/输出各可复制；原有整条复制保留为“复制原文”，取原始 `message.content`，不取预览。

系统消息仅对已知 session/terminal/turn_adopted 结构生成简短说明，提供原文；未知类型保留原值。历史失败事件与当前 `round_detail` 失败分开呈现，不能把旧失败重新标为当前阻塞，也不能把 terminal completed 写成任务全流程已完成。

### 4. 搜索和滚动共享明确的归属规则

搜索输入与已提交 query 分开，复用 `RunsView` 的 300ms 可取消防抖。 输入文本由搜索栏专用观察状态承载，逐键回显不发布整个阅读器状态；提交查询仍经原有 Store 的代数、消息版本与查询版本守卫。清除、回到最新及轮次切换保持同一输入与取消规则。过滤、高亮、长文预览策略共用 trim 后的 query；空白等价于未搜索，清除即时恢复。大小写不敏感匹配在原字符串上取得 range，用同一 range 高亮，避免 lowercase 后索引映射错误。

结果按原 seq 顺序。默认显示匹配字段名称和首个命中附近的有界上下文（仍 ≤512 字符），命中在预览外也可见；不因搜索把全部长输出展开。原文命中标“原文命中”，完整位置在只读全文浮层中定位。异步搜索结果同时校验 query 版本、消息版本与轮次 generation；消息更新或快速输入后旧结果不能覆盖新输入。

开始搜索时记录当前 run、首条可见消息的稳定 ID 与跟随意图；清除后恢复到原消息，而非强制到底部，同 ID 修订映射到当前行。搜索期间主动点击“回到最新”后以该意图为准；切轮次使旧锚点失效。查询和全文浮层的重试保留输入、折叠状态及有效锚点。

每个 generation 只允许一条有效读取链；进入 select/refresh 即取消旧轮询与搜索/定位任务，捕获请求 run/cursor，再启动读取。`has_more` 页连续串行读取，页间检查取消；读完后进入定时增量。重复刷新合并；旧请求的成功、错误和 loading 收尾均核验归属。

滚到底/保留锚点统一由一个可取消定位批次执行；每次延迟纠正前核验取消、批次号、run 和跟随意图。切轮次、离页、主动上滚及搜索重排取消不再适用的定位。保留现有原生几何和必要的两次延迟纠正，不能直接删掉后以 mock 通过代替原生稳定。

### 5. 局部视觉规格

继承 `Components.swift` 的 `kpTitle/kpBody/kpSmall`、`Spacing`、系统控件与 `MarkdownReaderView` 的只读呈现模式。以下是规划选择，尚未实施或由用户验收。

- 固定区域顺序：标题行 → 操作行 → 简要元数据/会话详情 → 当前错误横幅 → 搜索 → 消息列表 → 有新内容入口。标题 18pt semibold、正文 13pt、辅助信息 11pt、代码 12pt 等宽；系统语义颜色，间距 8/12/16pt。沿用现有正文行距与段距，不新增全局 token、大卡片、聊天气泡、阴影或组件库。
- 标题去掉 220pt 固定上限，最多两行，可复制和获取完整文字。轮次选项使用“开始时间 · 轮次状态 · run_id 前 8 位”；全局会话另带任务标题。完整 ID 留在会话详情与 help，不用长 marker 作主要可读名称。缺少标题/时间时显示已有明确占位，不捏造轮次序号。
- 控件行可用宽度 ≥840pt 时筛选、轮次与管理入口一行；<840pt 时分成“筛选/轮次”和“管理”两行。refresh 始终可见；宽度不足时将移入回收站/恢复/永久移除放带文字的“会话操作”菜单，仍显示禁用原因并沿原确认。900×600、侧栏展开时无控件横向裁切。
- 时间与配置只保留一处摘要；“会话详情”用现有 `FieldRow` 风格，宽处两列、窄处一列，长路径中间截断且完整可复制。精确 last_checked_at 放这里，按需展开；失败原因不受折叠影响。展开技术字段区独立滚动，高度不超过阅读器高度的 30% 或 200pt，避免窄窗因字段数量被迫增高或挤掉消息列表。
- 消息正文列最大 960pt，左对齐，随窄窗口收缩；行尾操作位于该阅读列内，使用系统 small 带边框按钮，保证展开/复制动作参与原生 Tab 顺序（不使用会跳过这些动作的 borderless 样式或额外焦点包装）。角色/时间一行、正文在下，条间使用轻量分隔及 16pt 间距，内部 8pt；短行高度 ≥40pt。正文可选择，工具输出换行不撑宽窗口。
- 内联展开的正文上限 64 KiB；超过时按钮为“查看全文”，打开新 `SessionMessageDetailView` 只读浮层，默认约 840×560，由呈现入口明确约束并按父阅读器可用宽高收缩（下限480×360），不依赖 GeometryReader 的最小固有尺寸选择，适应最小窗口。用户/助手可用“阅读 / 原文”，阅读复用 `MarkdownReaderView`；工具提供“输出 / 原文”，原文使用同类不可编辑 `NSTextView`。每个模式只有一个滚动区域，原文逐字可复制，不执行脚本、自动加载远端媒体或修改证据。
- 巨型纯文本全文（>64 KiB）使用独占后台 TextKit 1 图预布局：未附着 NSView 时设置字体、段落与真实容器宽度并完成布局，停止后台访问后按当前正文/宽度/generation 交接给只读 NSTextView。等待时显示“正在准备全文”，完整复制仍取原文；不插入断行、不截断、不用多个文本框拼接证据。主线程附着不得再次重写已准备正文/字体/容器宽度。窗口宽度变化重新后台准备，保留 UTF-16 阅读锚点和选区；过期/关闭结果丢弃。巨型“阅读”模式后台复用 `MarkdownBodyLayout.render` 生成原有块级富文本后走相同预布局交接，保留既有安全 Markdown 呈现；其渲染索引不能映射原文时仍先在原文模式定位。模式属于布局身份，过期模式结果不可覆盖。短文本复用既有入口。全文浮层使用该阅读器独占的原生 NSPanel（NSHostingView 内容），设置 animationBehavior=.none 后通过 makeKeyAndOrderFront 显示，不调用 beginSheet 或应用级模态循环，避免标准 AppKit sheet 展开/收起动画同步阻塞主线程。默认居中于所属父窗口，父窗口仍可操作；每个阅读器只保留一个全文窗口，关闭/父阅读器离页/切轮次时释放正文并返回原消息与有效阅读锚点，Escape 与关闭按钮行为一致。保持原系统颜色、840×560 与窄窗口夹紧规则，不改变其他页窗口/动画。准备、首次绘制、全文定位、缩放及释放全过程均按原≥250ms停顿阈值验证，不只测后台或定位调用耗时。
- Tab 可达筛选、轮次、详情、刷新、搜索、消息展开/复制；Enter 执行当前安全按钮，Escape 关闭全文浮层返回原消息。VoiceOver 读出角色、工具状态、命中字段、折叠状态及按钮用途；颜色不承担唯一语义。


### 4.6 归档与回收站列表（v2）

- 「归档」节：归档任务列表（沿用既有行规格与 `恢复` 操作）。
- 「回收站」节：顶部**两段控件** `任务 / 会话`（segmented，宽度自适应）：任务段列 trashed 任务，会话段列 trashed 轮次（`list-sessions save_state=trashed`）。
- 回收站行除 `恢复` 外提供 `永久从列表移除`（destructive）：`confirmationDialog` 二次确认，文案固定「永久从列表移除；保留历史记录与文件，不释放磁盘空间。」；调 `purge-task`/`purge-session`（带 `expected_save_state:"trashed"`）。
- 可选「清空当前分类」按钮：仅对**本次确认时快照的对象集合**逐项 purge（逐项失败单独报告，不中断其余）；不清理确认后新进入的对象。
- 空态区分：`回收站为空` / `没有执行会话`；purged 对象不出现（`list-tasks`/`list-sessions` 默认排除）。

### 4.7 规划面板（v2，protocol §5.22）

- 看板任务详情浮层的 `准备规划` 先关闭详情，在真实关闭回调后由主窗口呈现规划面板并传递当前任务 ID；重复点击合并，不用固定延时或竞争同一窗口的两个浮层。待处理/运行记录的内联详情保持原直接打开入口。进入第一步后首次成功读取定位该任务，核心可选时勾选，不可选时保留原因且不绕过限制；后续刷新保留用户修改的勾选状态。打开面板只读取配置与 To Do，不自动准备材料或提交规划请求。

- 入口：「任务」区工具栏 `规划待办…`；待处理/请求详情 `prepare_plan`/`fetch_todos` 动作。窗口约 760×600（sheet 或独立 Window）。
- **第一步 获取 To Do**：`刷新` 调 `fetch-todos`；列表行=标题、项目徽标、`local_status`（未导入/需重新规划/已有计划…）、附件计数、`selectable=false` 时灰显 + `blocked_reason`。仅 `selectable` 行可勾选进入下一步。
- **第二步 准备材料**：对勾选任务逐条 `prepare-plan-input`（自动或点 `准备`）：展示 `files[]`（名称/大小/来源）、`issues[]`（红图标+文字）、`can_start`；提供补充说明输入框、本地文件选择（`local_paths`）、失效附件排除（`excluded_remote_ids` 勾选）。`issues` 未清零前 `can_start=false`，开始按钮禁用并写明原因。
- **规划方式选择（T2，protocol §5.23.2）**：第二步增加明确的**两项**选择——`内置规划`（builtin）与 `Spec Planner 插件`（spec_plan）。默认预选取 `get-planner-config` 的 `default_method`（缺省 builtin）。`planner-capabilities.planner_methods.spec_plan.available=false` 时该项禁用并展示 `reason`；选择对本批次选中任务生效（每项 `start-plans` 带 `planner_method`），第三步提交前在汇总区明示所选方式。spec_plan 选项附边界说明：「该方式经 Codex 插件技能执行，可能加载本机用户配置中的其他能力（MCP/规则）；不使用隔离用户配置的只读内置链路。」普通规划/评审修复规划仍各自沿用既有模型/思考等级设置。
- **第三步 开始规划**：`开始规划` 调 `start-plans`（已勾选且 `can_start` 项批量提交）；逐行显示结果——成功 `已排队`、幂等 `已在队列`、失败 `code`+`error` 原文。成功后核心立即唤起规划 runner；面板显示进行中轮次与最近日志摘要。
- 已授权排队中的任务显示 `已排队等待规划`；旧未授权 plan 请求显示 `等待确认材料`（点行直接进入第二步）。
- 失败/加载/空态沿用 §6；面板不阻塞主窗口操作。

### 4.8 计划阅读页（T1，protocol §5.23.1）

- 数据源：`get-plan {task_id, expected_plan_sha256}`；进入时携带当前 `get-task` 的 plan_sha256 做预期核验。读取在后台进行，**任务切换/在途响应归属用 request generation 守卫**——旧任务响应不得覆盖新页面。
 - 头部（固定，不随正文滚动）：标题由父详情顶栏显示一处（最多两行，可选中复制）；父详情隐藏顶栏时，计划页补回同样的标题（18pt，**单独占满第一行且最多两行**，可选中复制）；`plan_kind`、生成时间、`plan_sha256` 前 12 位（可复制）与可截断路径置于元数据区（`待确认执行` 状态与标题同样只显示一处，见 §4.1），长路径**中间截断**但可复制并经 `在 Finder 显示` 定位；**渲染/原文**模式分段与 `打开计划文件`、`在 Finder 显示` 置于**独立操作行**（宽度不足时在该行换行），不与元数据争宽。右上无裁切、重叠或漂浮残字。底栏确认条与按钮可用性规则不变。
 - **渲染/原文双模式**：默认渲染视图以 Foundation `.full` Markdown 的 `PresentationIntent` 语义结构（标题/列表/代码/引用/分隔/GFM 表格）做**块级**原生排版，不用单个 `Text` 承载整篇，也不手写正则解析器；H1 用 18pt，其余标题/正文以 13pt 的字重与间距区分，代码沿用 12pt 等宽，颜色/分隔沿系统语义色。超宽单元格/代码行可换行或在内容区水平查看，不撑宽整个 sheet。原文模式逐字显示（含所有字符，不折叠/不重排）。两种模式正文均可选中复制，跨块选择保留合理换行及列表/表格内容。
 - **安全约束**：渲染**不执行**内嵌 HTML/脚本，不自动加载远端媒体（图片仅显示 alt/占位）；Markdown 链接以文字+图标显示，点击经 `NSWorkspace` 打开系统默认浏览器（仅 `http/https`）。页面内**不允许**修改计划内容。
 - **核验失败状态**（`get-plan` 返回错误）：保留任务摘要区，显示错误原因（中文）、`重试`、`打开计划文件` 入口；底栏执行确认（`confirm_dispatch` 等写操作）**保持禁用**直到核心重新核验通过——不把不可信正文当作已批准计划展示，也不允许「确认并安排执行」。
 - `plan_sha256` 与 `expected_plan_sha256` 不符（`conflict`）：展示「计划自发布后已变更」+ `重试`/`在 Finder 显示`；不渲染旧快照。

### 4.9 角色化设置页（T5，protocol §5.23）

- 顶层侧栏仍只有「设置」；设置页内部以 `规划环境 / 执行环境 / Review 环境 / 通用` 四段切换（segmented，**不按** Codex/PI 软件名分节）。沿用 grouped Form、现有控件密度与系统语义色。
- **规划环境**：Codex 认证/服务商只读区（`planner-capabilities`）、两组模型与思考等级（§5.22.6）、`planner_methods` 可用性与 `default_method` 预选（含 spec_plan 的边界说明文字）。
- **执行环境（v4 扩展）**：任务执行者后端切换（`pi` / `pi_desktop`）；另设「派发与监控运行端」`Pi CLI / Pi-Desktop-Plus`（`exec_config.controller_backend`，缺省 Pi CLI）。pi 分支为四选择器（§4.4 原 PI 执行配置内容），pi_desktop 分支为连接文件路径（`mcp-control.json`）、provider/model/thinking_level/`permission_mode` 选择——**permission_mode 首次须用户显式保存**，不得自动选 `auto`。两分支各自的能力检查列表与 dispatch/monitor 调度状态行；控制器就绪态与任务执行就绪态分开显示。
- **T3 Plus 执行环境细节（T3.5）**：桌面标签为 `Pi-Desktop-Plus（本机 MCP）`，tag 仍 pi_desktop；path 草稿为空时填入 `~/.pi-desktop-plus/mcp-control.json` 的绝对路径，仍可手改。切入 Plus 时调用只读 `pi-desktop-catalog` 取本地 provider/model 候选与 Plus 默认值；默认组合只填空草稿，不改已有配置；「重新获取」刷新候选，不覆盖非空草稿。provider/model 保留可编辑 ID 和离线保存能力，并以候选弹出列表选择；model 候选有独立搜索词。thinking 依据 Plus 明示的模型/provider级别展示，缺少级别信息时显示全合法枚举并标记支持范围未确认。permission_mode 必须用户显式选择，绝不读取 Plus 会话或自动设为 auto。「检测已保存配置」仍只检查已保存配置；读取/检测各自显示状态，不互相覆盖。加载失败保留草稿，错误详情优先 detail 再 reason 且允许换行；读取期间用户修改或切走后丢弃过期响应。桌面保存只校验五字段，不受 PI CLI 顶层 ok 阻挡；保存 pi 不提交空桌面块，保存桌面不提交无关 CLI 草稿。保留 grouped Form、四段、字号与间距，不变更全局设计。
- **Review 环境**：`get/set-review-config`——`inherit`（继承本机 PI 默认会话配置）/ `custom`（provider/model/thinking 由 `exec-capabilities` 校验的显式选择）；显示当前生效来源与「仅影响下一次 review 启动」说明。
- **通用**：doctor、自动推进/暂停、队列参数、路径、迁移信息（把 §4.4 原「环境诊断/自动推进/路径/迁移」归入）。
- 各页保存失败保留草稿与核心 error 原文；加载失败保留旧内容 + `重试`；标注「默认/已保存」与「仅影响新轮次」。不修改 `~/.pi`、`~/.codex` 或 PI-Desktop 全局配置。

### 4.10 角色后端选择与 Plus 接入显示（T6，protocol §5.24）

- 四段设置与 grouped Form 不变。**规划环境**增加后端选择 `Codex / Pi-Desktop-Plus`；Plus 分支复用已存在的五字段与 `pi-desktop-catalog` 候选控件，新规划权限固定 `auto`，说明工具无需逐次确认、可运行命令和修改规划工作目录文件；Review 权限固定 `auto`；选择 Plus 时 `builtin` 可用、`spec_plan` 禁用并显示原因（spec_plan 是 Codex 插件运行方式）。标准/修复两组 Codex 模型块保留在其分支；切到 Plus 不得重载配置覆盖草稿。
- **执行环境**的两个选择——任务执行者（`exec_config.backend`）与「派发与监控运行端」（`exec_config.controller_backend`）——分别显示当前生效值与各自能力状态；Plus 控制端复用本页已保存的 Plus 型号字段。禁止把一个 Plus 选择表现成「全链路已切换」。
- **Review 环境**增加独立后端选择；`pi` 分支保留 `inherit/custom`，Plus 分支复用目录候选并固定 `Ask`，不混用任务执行 `agent_preset`。
- 「获取 Plus 列表」沿已有只读动作；只在目标角色的**空草稿**里填 Plus 明确默认值，不因一次查询改写其他角色。每个角色独立保存，成功/失败沿现有 toast/alert，失败保留草稿；提示「仅影响新请求/新控制轮」，运行记录始终显示快照值。
- 规划面板第三步提交前显示本次请求的后端、型号与方式；任务详情/记录显示每阶段 backend、会话与 turn，以及权限等待/连接不可用/输出错误等状态。外部查看沿现有路径与会话标识入口；没有已核实的 Plus 深链时只展示 ID，不编造链接。
- 键盘与 VoiceOver：新增的后端选择器与候选弹层沿用 §7 的焦点顺序与可读名称；错误文案允许换行，不遮挡保存按钮与权限选择。

## 6. 反馈与空态（全部必须实现）

- 加载：列表区中央 `ProgressView` + `正在读取…`；命令执行中按钮转 disabled+spinner。
- 空队列：`暂无任务`/`暂无待处理项` + 一句说明 + `刷新` 按钮。
- 离线/核心不可达：顶部横幅 `无法连接调度核心：<原因>` + `重试`；数据保留展示并标 `可能已过期`。
- 读取失败：错误横幅（红图标+文字）+ `重试`；不清空旧数据。
- 操作成功：短暂确认（工具栏旁 `checkmark` + 文字或轻量 toast），并立即刷新数据。
- 操作失败：alert 或横幅给出核心返回的 `error` 原文。
- 禁用：按钮置灰 + tooltip/标签写明原因（如 `已有活动派发请求`）。
- 危险操作（accept_duplicate、mark_done、release_lost、restore、purge-task、purge-session）：`NSAlert`/`confirmationDialog` 二次确认，写明后果；purge 文案固定「永久从列表移除；保留历史记录与文件，不释放磁盘空间。」

## 7. 键盘、焦点、无障碍

- 列表支持 ↑↓ 选择、回车进入详情、⌘R 刷新；按钮有默认快捷键不冲突。
- 所有可点控件系统 focus ring 可见；`Tab` 顺序合理。
- 每个图标状态配 `.accessibilityLabel`（中文状态名）；按钮均有文字标题或 label；列表行 `accessibilityElement(children: .combine)` 读出一条完整摘要。
- 状态永远「图标+文字」双编码；不依赖颜色单独传达。
- VoiceOver 通过 macOS 辅助功能检查清单核验（见 tests/ui-acceptance.md）。

 ### 4.15 总览收件箱首页（attention inbox）

 **收件箱聚合规则：**

 - 行高 ≥40pt；分隔用系统 `Divider`。
 - 支持键盘 ↑↓ 选择、回车进入详情、⌘R 刷新。
 
 **详情展开（选中卡片）：**

 - 底栏操作区由 `get-task` / `get-request` 返回的 `allowed_actions` 渲染，映射规则沿用 §4.1 与 §4.2。
 
 **操作入口：**
 - 「安排下一步」进入已验证计划页（confirm_dispatch）；发送不明不自动选风险决议，以重新校验为安全入口。
 - 危险操作保留二次确认（accept_duplicate、mark_done、release_lost、restore、purge）。
 - 概览底栏一个安全推进主动作，低频动作进「更多操作」。
 
 **空态：**
 - 无待处理项时显示「暂无待处理项」+ 说明文字 + `刷新` 按钮。
 - 加载中显示 `ProgressView` + 「正在读取…」。
 
 **过滤与搜索：**
 - 工具栏搜索框（标题/项目匹配）+ 阶段筛选菜单。
 - 输入即时可见，300ms 防抖后提交。
 
 **与侧栏其他节的联动：**
 - 点击「任务」→ 完整任务列表；点击「待处理」→ 请求级详情；点击「运行记录」→ 事件时间线。
 - 收件箱卡片跳转沿用既有详情容器与五段导航，切换不丢当前任务。
 
 **冻结度量复核：**
 - 正文 13pt、区段标题 18pt semibold、辅助信息 11pt。
 - 间距 8/12/16pt；列表行高 ≥40pt。
 - 默认 1180×760，最小 900×600。

沿用设置页现有规划/Review 运行端 Picker、模型编辑器、FieldRow、字体与间距，仅各新增「Qoder CLI」。两角色分别保存模型与思考等级，默认 auto / inherit（继承 Qoder 默认）；可输入 CLI 支持的模型标识，思考等级不冒称对所有模型均可用。仅 builtin 可用于 Qoder 规划，默认方式为 spec_plan 时明确提示先调整；切换后端保留其他草稿和已存字段。规划面板的普通/修复型号摘要读取已存 Qoder 配置，明确禁用 Spec Planner，发送 builtin。就绪提示区分未安装/接口不可用与认证、模型尚未验证；保存不要求在线、不调用模型、不修改 Qoder 全局配置。主 agent 用隔离原生候选核验两个入口、保存重读、切换后保留配置和未安装提示。


## 手机连接与 Android 控制台（2026-10-21）

macOS 在现有连接设置页加入手机连接开关、绑定网卡/端口、5 分钟配对二维码、复制配对内容和设备撤销；继承现有字体间距与布局。开启与服务 ready 分别展示，关闭窗口保留服务，退出停止本实例拥有的服务。Android 使用 Material 3 系统浅深色、16dp 边距与至少 48dp 点击区，底部为总览/任务/需要你/连接，任务详情为概览/计划/执行/评审/记录；其余行为遵循 [安卓控制台契约 v1](mobile-console-contract.md)。前台 5 秒刷新，后台停止；断线保留旧内容和答案草稿并禁用写操作，迟到请求不能覆盖新任务。暂停称“暂停自动推进”，明确运行中的会话继续。
