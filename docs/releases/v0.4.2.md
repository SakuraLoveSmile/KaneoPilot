# KaneoPilot v0.4.2

## 新增

- **AI 辅助填写发布配置**：根据仓库资料建议工作流、运行分支、初始版本、安装包名称和必需 job，展示建议依据与缺失项。分析前显示模型及费用提示；采纳只填入草稿，仍由你确认保存。手动编辑或切换项目后，旧建议不会覆盖新草稿。
- **任务整理**：任务右键菜单增加“移入回收站”，沿用确认和恢复流程；同项目任务集中展示并可折叠，搜索与批量选择遵守当前可见范围。
- **完成任务自动归档**：在“设置 → 高级 → 诊断与数据”按全局配置保留天数，支持 1–3650 天，默认关闭、默认保留 7 天。归档保留记录且可恢复；需要本机引擎运行并且未全局暂停。
- **Codex 评审模型列表**：在评审配置中直接选择本机模型目录，同时保留手动输入、自定义模型和离线保存。

## 修复与改进

- **降低配对二维码密度**：二维码采用紧凑内容，放大为 300pt，增加白色静区并避免模糊缩放；保留证书指纹、TLS 主机名校验、五分钟有效期和单次使用限制。
- **项目列表与 Kaneo 同步**：完整刷新成功后，已删除或归档的云端项目不再显示；离线或刷新失败继续使用上次成功列表。原仓库映射、任务与历史记录仍保留。
- **修复项目设置保存栏遮挡**：多个开关、较长改动名称和发布配置错误提示可以换行，正文与底部保存栏分别布局，保留保存、放弃及原有确认流程。
- **自动接收记录更易读**：原“接收详情”改名为“自动接收记录”，增加用途说明，优先显示项目名称，项目 ID 放在展开内容中。

## 引擎变化与升级说明

- 普通项目统一由新 Live 引擎调度，移除 Legacy/Shadow 模式选择；启动时迁移历史模式并保留审计记录。自动处理开关、暂停、预算、人工确认和发布策略继续生效，已有轮次不会因此重新发送。
- 旧 `pi` 任务执行后端不再接受新执行；请在执行配置中选择 Plus 或 Codex CLI。规划与控制端的 `pi` 兼容保留，历史配置与记录仍可查看。
- 紧凑二维码需要本版 Android 控制台；旧 Android 客户端仍可粘贴 Mac 的“复制配对内容”进行配对。
- macOS 安装包仅支持 Apple Silicon（arm64）、macOS 14 及以上，内置 Python；采用 ad-hoc 签名，未公证。从旧 Universal 安装版本升级仍需手动安装一次 arm64 包。Android 最低版本为 8.0，正式签名身份保持不变。
- 本次不新增数据库 schema 版本。真实手机拍摄扫码及真实模型调用尚未做验收，仍待使用反馈。
