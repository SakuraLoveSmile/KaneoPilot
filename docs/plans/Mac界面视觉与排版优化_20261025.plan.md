# Mac 界面视觉与排版优化

## 概要

对象：macOS「Kaneo 调度台」的总览、任务列表、任务详情浮层、侧栏与工具栏、命名，以及执行页的复盘。要解决四类问题：信息太密、重点不突出；颜色与对比度不足；入口拥挤、叫法不统一；观感不像原生 Mac。

对照材料：设计画布（私有，仅作者可打开）https://claude.ai/artifact/DeJQQDPpkKegs3EspV2A1f 。「当前」画板由代码还原，不是真实截图；「优化后」是示意稿，高度、宽度为估算（约 ±15%）。画板与本文有出入时以本文为准。

状态：待确认项已全部确认（2026-10-25），等待开工批准。本文是唯一新增的文件；`macos/`、`docs/ui-spec.md`、`AGENTS.md` 均未改动，未构建、未安装、未提交。

用户已确认（2026-10-25）：

1. 状态与叫法全部采用：列表与详情的状态徽标取核心 `exception.label`，不再一律写「阻塞」；入口统一叫「需要你」；筛选「阶段」改叫「看板列」。
2. 「暂停自动推进」与「刷新」移到侧栏底部的状态块；工具栏只在已暂停时出现橙色「已暂停 · 恢复」胶囊。
3. 采用扩展刻度：字号 11/12/13/15/18/22pt，间距 4/8/12/16/24；区段标题 18pt 降为 15pt。
4. 状态色沿用与 Android 共用的色相映射，Mac 只调色值与对比度。
5. 阻塞证据折叠行放在问答之后（首屏之外）；ui-spec §4.17 `:507` 的顺序句随之改。
6. 工具栏的「更多」和详情浮层的「关闭」都改成图标按钮；规格 §2 `:22` 的「每个控件都有可见文字」为这两处加例外，须有 `accessibilityLabel` 和 `help`。
7. 时长统一写「N 分钟」，规则见 S8。
8. 执行复盘按计划重排：4 项关键指标，其余折叠，时间分布并进泳道，泳道按状态色。桌面泳道换色后与 Android 不再同色，只改桌面，安卓暂不动。
9. 把 `run-completion-display-fixtures` 加入 `packages.yml` 的桌面夹具清单（S9）。
10. 设置页 `SettingsView.swift:2478` 的「待处理事项」改「需要你处理的事项」（S3 第 5 条）。

第 5–10 项原先是按画布默认处理、未单独问过的内容，已在同日第二次提问中逐项确认，均采用推荐方案。

## 边界

- 不动 Android，也不改 `docs/mobile-console-contract.md`。两端因此产生的差异见「风险」第 9 条。

### 总览

- 三个主区段（需要你、流水线、正在推进）之后是项目自动化和环境；区段标题 15pt，各区段用分组容器（圆角 10）代替分隔线。
- 「需要你」每条两行：第一行标题与原因（原因文字用 `.primary`），第二行「项目 · 阶段 · 自 HH:mm」（11pt 次要色）；右侧一个按钮，文字取核心推荐动作（`Labels.action(recommended)`，如「回答执行问题」「重新规划」「释放失联请求」）。去掉「下一步：」行、「等待自」、箭头。行高 52。
- 流水线五个计数用 22pt 指标数字；说明句保留「已排队不等于已开始，执行端领取后才开始」。
- 「正在推进」每条两部分：标题加项目；右侧「阶段 · 条件」（如「执行 · 执行中」）。8 步进度条不再在总览出现。
- 环境区去掉「暂停自动推进」按钮；诊断详情与引擎记录仍默认折叠。
- 搜索进工具栏（`.searchable`）；阶段菜单留在「需要你」区段头。

### 任务列表

- 行是扁平行加缩进分隔线，不再是描边卡片；选中或焦点用强调色 10% 底。
- 第一行：标题（13pt）加项目名（11pt 次要色）；右侧状态徽标（图标加文字）和更新时间。第二行只在需要时出现：异常或等待原因（`.primary`，12pt）、二级任务的来源说明。去掉行首图标，状态只由右侧徽标表达。
- 「原始任务」只在有层级时出现；「会话」按钮仅悬停或聚焦时显示。
- 单行 ≥40，两行 52。分组头 11pt 半粗，计数用胶囊。
- 看板列取色对齐手机端看板汇总（`docs/mobile-console-contract.md:174`）：待规划、待办灰，进行中蓝，待评审橙，阻塞 / 失败橙，已完成绿。

### 任务详情浮层

- 浮层尺寸不变（`BoardView.swift:1531`：最小 720×520，理想 840×640）。
- 头部：第一行任务标题（18pt，最多两行，可选中）加右上角图标关闭按钮；第二行一行元信息「项目 · 状态徽标 · 已等待 30 分钟」；第三行 280×28 的分段控件。去掉项目灰块和「阶段：…」。状态只说一次。
- 概览首屏：一行下一步说明在前，然后是「回答 N 个问题」（15pt）。每题：序号、标题、「单选 / 多选」标记、右侧「跳过此题」文字按钮、说明；选项做成分组列表（圆角 10，行 ≥48，带说明的选项两行；选中项淡蓝底加勾选；「自定义回答」为最后一行）。题与题之间留 16–24 的间距，不用分隔线。底栏不变：「提交答案」加「还差第 N 题」加「更多操作」。
- 首屏之后：阻塞证据（折叠行）、进展（8 步一行，被阻塞的那一步用橙点标出；条件仅在与状态不同时显示）、任务信息（项目、层级、Kaneo、交付、自动处理五行，放进一个分组容器）、技术详情与路径（折叠）。
- 估算纵向结构：优化前全部内容约 1152px、首屏 520px（45%）；优化后约 897px（含阻塞证据折叠行 44px）、首屏 496px（55%）。按这些数推算，回答表单底边在首屏约 485px 处，余量只有约 11px，小于估算误差（±15%），所以「整份回答表单落在首屏内」是推算结论，要在实机上核对。这些是按代码推算的估算，不是实测。

### 执行复盘
