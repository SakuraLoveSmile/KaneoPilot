## 签名包实测

2026-11-25，Apple M1 Pro，macOS 27.2.1。本机构建的 arm64 Release 实验包 `0.5.10-perf.1` 与现装 `0.5.10-test.451` 各使用其内置 Python 3.13.18。使用 `tests/bench_read_commands.py` 的临时库，33 项任务、16,069 条请求、53,308 条事件，含评审父子关系、证据 JSON 和规划会话。每个场景新开 CLI 进程，预热一次后取 7 次墙钟中位数。机器同时有其他后台验证，绝对值受负载影响。

| 读取 | 现装版 ms | 实验包 ms |
| --- | ---: | ---: |
| 空库总览 | 366.74 | 106.24 |
| 历史库总览 | 503.36 | 171.30 |
| 运行记录首屏 | 827.05 | 92.00 |
| 按任务及游标取事件 | 340.00 | 98.88 |
| 稀疏筛选取事件 | 946.49 | 112.76 |
| 任务列表 | 1009.60 | 161.79 |
| 任务详情 | 522.66 | 179.66 |
| 评审列 | 776.28 | 146.37 |
| 会话列表 | 478.89 | 102.70 |

九个场景的 JSON 逐字段相等，总览分别核对核心路径后归一化该路径。现行评审风险和 AI 操作字段均进入对照。运行记录首屏子进程峰值 RSS 从 178.8 MiB 降至 34.9 MiB（每侧预热一次，三次中位数）。原三条状态命令并发对单条 `desktop-status`，交替运行、预热后各 11 次，中位数为 316.2 / 89.0 ms，三组返回值一致。SQLite WAL 回归在持有未提交写事务时核对旧快照，并验证提交后新暂停值可见。

macOS 使用项目支持的本地 `scripts/build_app.sh` 入口独立构建。Xcode 27 beta 的首次启动检查返回 69，但 macOS SDK、编译、链接、打包、ad-hoc 签名与严格签名核对均可直接在后台完成；没有修改系统开发组件。核对了包内全部 175 份 Python 源文件及其对应字节码头的魔数、模式和源码指纹。

## 原生界面实测

同一台 Mac、同一组合成历史，基线和实验版各自使用对应的 SwiftUI 源码及签名包内的核心。离屏 NSWindow 以 1180 × 760 点挂载真实总览和任务详情，用计数出现与详情概览出现作为终点，在主线程布局及显示后取样。各预热一次，用固定随机顺序交替运行，每个版本每页 20 次。所有进程均回报未取得前台焦点。

| 首次显示内容 | 现装版源码 p50 / p95 | 实验版源码 p50 / p95 | p95 缩短 |
| --- | ---: | ---: | ---: |
| 总览计数 | 1,560 / 2,202 ms | 455 / 516 ms | 77% |
| 任务详情概览 | 706 / 791 ms | 384 / 434 ms | 45% |

首轮离屏截图核对到统计数字和任务 `fixture-task-01` 的「待收尾校验」内容。总览可以在项目列表返回前显示计数。实验包旁的 `evidence/core-read-benchmark.json` 和 `evidence/native-first-content-ms.json` 分别保留命令对照和原生首屏的逐次耗时。

另用真实运行记录列表做三轮离屏交互，每轮约五秒。滚动列表期间触发周期刷新，并通过同一筛选模型连续输入三个搜索前缀。每轮完成 264–272 次滚动位置变更，最终均显示 100 条结果。主线程 60 Hz 定时回调的间隔 p95 为 23–32 ms，三轮各自最长为 135、83、143 ms。这是离屏主线程响应性抽样，实际桌面滚轮、键盘和显示器帧时间仍待前台体验。

另测能确认没有任何匹配的自由文本搜索。双方均返回空列表，七次中位数从 819 ms 减至 539 ms。无匹配时仍需扫描全部 53,308 条历史，比当前包的默认首屏读取慢约 6 倍，是后续优先调研的路径；若引入搜索索引，需要维持历史来源标题回填、任意子串及游标顺序。

后台每轮状态读取的三个旧子进程合计 CPU 时间，中位数为 818 ms，实验版单个子进程为 95 ms，降低约 88%。每个版本预热一次后交替测 11 轮，每轮验证三块状态内容一致；计时取操作系统回收子进程时报告的用户与内核 CPU 时间。该指标仅覆盖状态读取的子进程。

## T5 搜索无匹配时的等待

基线是第一轮实验包 `0.5.10-perf.1`（`332e74f`）。第二轮在同一实验分支生成 `dist/kp-perf01-search/KaneoPilot.app`，版本 `0.5.10-perf.2`。界面通过原有 300 ms 输入防抖发起搜索。核心先检查文本，命中才读取关联请求的阶段与结果，并构造要返回的完整事件。单次查询内共享任务显示文本和重复的小型事件内容；独特或较大的历史详情仍按原有中文摘要和规范化 JSON 语义搜索。查询结束即释放缓存，无数据库迁移。

同一台 M1 Pro 上，两个签名包使用各自的内置 Python。数据库有 53,308 条事件，另测每行均有不同中文说明、请求标识和嵌套证据的同规模历史。每个版本、每个核心场景预热一次，各跑 7 次，比较完整事件与游标。取墙钟中位数：

| 场景 | perf.1 | perf.2 |
| --- | ---: | ---: |
| 英文无匹配，重复事件详情 | 650 ms | 167 ms |
| 中文无匹配，重复事件详情 | 657 ms | 167 ms |
| 英文无匹配，53,308 种不同详情 | 691 ms | 306 ms |
| 中文无匹配，53,308 种不同详情 | 725 ms | 311 ms |
| 稀疏命中，带阶段和结果筛选 | 111 ms | 94 ms |
| 稀疏命中的后续页 | 107 ms | 90 ms |

原生离屏测试先显示 100 条历史，再用搜索框绑定的同一模型方法更新搜索词。实际的 SwiftUI「无匹配事件」出现、完成布局并提交显示时结束计时，包含输入防抖、启动核心进程和界面刷新。每个版本每种历史预热一次、各测 20 次，所有测试窗口均在后台。

| 从输入到空状态 | perf.1 中位数 / p95 | perf.2 中位数 / p95 |
| --- | ---: | ---: |
| 重复事件详情 | 1,209 / 1,368 ms | 745 / 812 ms |
| 每条事件详情都不同 | 1,292 / 1,538 ms | 938 / 1,078 ms |

此次按影响范围运行 50 项核心回归、13 个子测试和 8 项数据库集成检查，全部通过。另对 174 组搜索逐字段比对上一实验包，包含中文摘要、Unicode 大小写、历史来源标题、字段间换行、转义与数字的 JSON 表示、空页与游标。回归测试明确检查无匹配时关联请求读取和完整事件构造次数均为零。无匹配仍需扫描全部历史，详情各异时耗时更长。绝对耗时来自本机合成数据与离屏视图，真实输入设备的延迟尚未测量。

可复跑的命令基准 `tests/bench_read_commands.py` 已包含常规与不同详情的无匹配场景，全部 11 个对照场景输出相等。原始数据保存在实验包旁的 `evidence/`。测试结束核对临时目录无打开文件后已删除本轮构建、模块缓存、下载的运行时、测量程序和隔离数据库，合计 477,424 KiB（约 466 MiB）。
