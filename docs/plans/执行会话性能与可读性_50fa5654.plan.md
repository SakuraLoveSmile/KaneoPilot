## 关键设计决策

### 1. 核心采用跨进程的小元数据快路径

CLI 每次是新进程，不使用 Python 全局缓存解决轮询；也不为本次引入常驻读取 daemon 或数据库迁移。

新增内部键 `settings["session_snapshot_meta:<task_id>/<run_id>"]`，仅由核心命令写。字段为 `cache_schema:1`、`source_signature`、`source_version`、`record`、`max_seq`、`full_snapshot_available`。`record` 仅保存现有 SessionInfo 的来源摘要，不复制消息数组或完整 job 内容。签名包含规范化 runs 根、task/run/backend，以及 job/events 的 `dev/ino/size/mtime_ns/ctime_ns`；版本为规范化签名的 SHA-256。读取前后签名一致且解析新鲜成功，才保存该版本。保持现有路径越界、job 身份、后端和符号链接规则。

公共增补只涉及 `session-messages`：

| 方向 | 字段 | 行为 |
| --- | --- | --- |
| 请求 | `source_version?: string` | 调用方已读完该版本；未知或不匹配版本走正常读取 |
| 请求 | `force_reload?: bool`，默认 false | 强制读取来源，仍使用显式 cursor 做消息补齐，不清空 UI |
| 响应 | `source_version: string|null` | 只在稳定、成功的来源读取或已确认快路径返回有效值；失败/兜底/pending/unavailable 返回 null |

只有当前身份核验成功、前后签名稳定且与 meta 相符、请求版本与 meta 相同、显式 cursor 已到达 `meta.max_seq`、未要求强制刷新时，才返回 `messages=[] / has_more=false / 原 cursor`。此时不读 events 正文、不解码完整快照、不转换/排序消息、不序列化全文，也不解码大 revision map；仅更新读取位点的状态检查时间，并按当前 job/索引/时钟派生 SessionInfo 与允许操作。用 `session_store` 中的小型 touch 入口更新原字段，桌面仍不直接写库。

UI **仅在当前来源版本的分页全部读取完成（`has_more=false`）后**保存可确认版本；切轮次/重新打开清空，手动刷新传 `force_reload:true`。串行分页时不把未读完页的版本用于快返。旧客户端缺少字段继续正常读取，旧快照缺少 meta 时冷解析后升级内部缓存。首次无 cursor 必须仍读完整历史，不能拿数据库位点跳过正文。

超过现有 2 MB 全文快照上限时，成功解析后仍可保存小 meta，标记 `full_snapshot_available:false`；已读完的 UI 可使用无变化快路径。源变化、重新打开或强制刷新仍读来源。meta 不能代替最后有效全文：超限会话仍依赖 App 保留已加载正文；已有完整旧快照仍沿原失败兜底，不能声称已保证最新大文件跨进程恢复。

全文快照只在源版本变化且新鲜读取成功时尝试保存。文件追加、同尺寸改写、替换、截断、root/身份变化、半写失败必须使快路径失效；签名变化期间不重复盲读，不确认该版本，下次正常定时检查再读取。`get-session` 内部复用本次 `_associate` 已解析的事件生成 `round_detail/startup_turn_id`；引用内部 `_events`，不将它加入公共 JSON 或快照。

**本次维持既有 `seq:<n>` 游标、revision 映射与监控分页协议。** 已发现仅旧消息修订时响应游标可回退、首页 revision map 收入未来消息，以及 UI/monitor 共享修订位点的相邻问题；这些不是本次快路径的实现前提。本计划不顺带改自动监控。T1 的兼容检查须证明末端确认、重新打开、修订与分页没有因快路径被跳过；发现新增回归必须修正快路径，不靠修改监控完成判定消除失败。

源确实变化时仍走现有全量解析，因此本计划承诺降低无变化轮询成本和界面重复工作，不将其描述为完整的日志增量索引。

### 2. 展示准备只随消息变化，不随每帧变化

保留 `SessionMessage` 原始字段。新增会话专用 `SessionMessagePresentation.swift`，准备结果按 `(run_id, id, revision)` 归属当前阅读器；等价重发不重做，切轮次释放旧会话结果。准备正文、判长、预览、可读工具字段及搜索素材在后台进行，主线程只应用属于当前 generation 的结果；不引入全局缓存、磁盘缓存或更换状态框架。

预览采用双上限：最多四个可见行、最多 512 个 Unicode 字符；遇到第五个换行或达到字符预算即停止取预览，追加省略标记。判长沿现有“超过四行或 320 字符”，用有界扫描判断，不在行 body 中每次 `text.count/split` 整篇。单行 JSON 同样受限。可访问性名称只含角色、时间、状态与有界摘要；全文在阅读浮层可读取，不每次将巨大原文拼入行的 AX label。

元数据栏与消息区使用独立、稳定的观察输入。`last_checked_at` 更新只影响时间信息，不触发正文解析、搜索全量计算或高亮准备；following/hasNewContent 只在值变化时发布。复用已有 `applyMessages` 的等价比较与折叠迁移，列表仍用懒加载。

### 3. 工具展示只识别已知结构，原文保持完整

优先使用结构化 `SessionTool.name/input/output/exitCode`。对于截图这类包装，在展示准备阶段识别 `content:[{type:"text"或text字段}]`，取文本内容；该文本本身是 JSON 且含 `command/commandShellId/stdout/stderr/exitCode/exit_code` 时，再解码一层，最多两层。不做递归字符串替换，不把任意字面量 `\n` 改成换行，不执行内容。

自动解码预算为单条候选原文 ≤256 KiB；超限或未知结构显示“原始工具结果 · 大小”与有界预览，提供全文原文入口。解析失败不是任务失败，也不能伪造输出或丢掉原文。多 text 项保持原顺序；存在非 text 项时保留原文入口和“另有原始内容”提示。只对明确提供的整数退出码显示“退出码 0”或“退出码 N”；缺失时显示“状态未提供”，不能由 stderr 为空推断成功。

折叠状态显示工具名/命令摘要、状态文字和输出前四行。展开后按“输入 / 标准输出 / 标准错误”分区，不再同时重复打印包装 JSON、正文和相同 output。输入/输出各可复制；原有整条复制保留为“复制原文”，取原始 `message.content`，不取预览。

系统消息仅对已知 session/terminal/turn_adopted 结构生成简短说明，提供原文；未知类型保留原值。历史失败事件与当前 `round_detail` 失败分开呈现，不能把旧失败重新标为当前阻塞，也不能把 terminal completed 写成任务全流程已完成。

### 4. 搜索和滚动共享明确的归属规则

搜索输入与已提交 query 分开，复用 `RunsView` 的 300ms 可取消防抖。过滤、高亮、长文预览策略共用 trim 后的 query；空白等价于未搜索，清除即时恢复。大小写不敏感匹配在原字符串上取得 range，用同一 range 高亮，避免 lowercase 后索引映射错误。

结果按原 seq 顺序。默认显示匹配字段名称和首个命中附近的有界上下文（仍 ≤512 字符），命中在预览外也可见；不因搜索把全部长输出展开。原文命中标“原文命中”，完整位置在只读全文浮层中定位。异步搜索结果同时校验 query 版本、消息版本与轮次 generation；消息更新或快速输入后旧结果不能覆盖新输入。

开始搜索时记录当前 run、首条可见消息的稳定 ID 与跟随意图；清除后恢复到原消息，而非强制到底部，同 ID 修订映射到当前行。搜索期间主动点击“回到最新”后以该意图为准；切轮次使旧锚点失效。查询和全文浮层的重试保留输入、折叠状态及有效锚点。

每个 generation 只允许一条有效读取链；进入 select/refresh 即取消旧轮询与搜索/定位任务，捕获请求 run/cursor，再启动读取。`has_more` 页连续串行读取，页间检查取消；读完后进入定时增量。重复刷新合并；旧请求的成功、错误和 loading 收尾均核验归属。

滚到底/保留锚点统一由一个可取消定位批次执行；每次延迟纠正前核验取消、批次号、run 和跟随意图。切轮次、离页、主动上滚及搜索重排取消不再适用的定位。保留现有原生几何和必要的两次延迟纠正，不能直接删掉后以 mock 通过代替原生稳定。

### 5. 局部视觉规格

继承 `Components.swift` 的 `kpTitle/kpBody/kpSmall`、`Spacing`、系统控件与 `MarkdownReaderView` 的只读呈现模式。以下是规划选择，尚未实施或由用户验收。

- 固定区域顺序：标题行 → 操作行 → 简要元数据/会话详情 → 当前错误横幅 → 搜索 → 消息列表 → 有新内容入口。标题 18pt semibold、正文 13pt、辅助信息 11pt、代码 12pt 等宽；系统语义颜色，间距 8/12/16pt。沿用现有正文行距与段距，不新增全局 token、大卡片、聊天气泡、阴影或组件库。
- 标题去掉 220pt 固定上限，最多两行，可复制和获取完整文字。轮次选项使用“开始时间 · 轮次状态 · run_id 前 8 位”；全局会话另带任务标题。完整 ID 留在会话详情与 help，不用长 marker 作主要可读名称。缺少标题/时间时显示已有明确占位，不捏造轮次序号。
- 控件行可用宽度 ≥840pt 时筛选、轮次与管理入口一行；<840pt 时分成“筛选/轮次”和“管理”两行。refresh 始终可见；宽度不足时将移入回收站/恢复/永久移除放带文字的“会话操作”菜单，仍显示禁用原因并沿原确认。900×600、侧栏展开时无控件横向裁切。
- 时间与配置只保留一处摘要；“会话详情”用现有 `FieldRow` 风格，宽处两列、窄处一列，长路径中间截断且完整可复制。精确 last_checked_at 放这里，按需展开；失败原因不受折叠影响。
- 消息正文列最大 960pt，左对齐，随窄窗口收缩；行尾操作位于该阅读列内。角色/时间一行、正文在下，条间使用轻量分隔及 16pt 间距，内部 8pt；短行高度 ≥40pt。正文可选择，工具输出换行不撑宽窗口。
- 内联展开的正文上限 64 KiB；超过时按钮为“查看全文”，打开新 `SessionMessageDetailView` 只读浮层，默认约 840×560，适应最小窗口。用户/助手可用“阅读 / 原文”，阅读复用 `MarkdownReaderView`；工具提供“输出 / 原文”，原文使用同类不可编辑 `NSTextView`。每个模式只有一个滚动区域，原文逐字可复制，不执行脚本、自动加载远端媒体或修改证据。
- Tab 可达筛选、轮次、详情、刷新、搜索、消息展开/复制；Enter 执行当前安全按钮，Escape 关闭全文浮层返回原消息。VoiceOver 读出角色、工具状态、命中字段、折叠状态及按钮用途；颜色不承担唯一语义。

## 风险与规避

| 当前有依据的风险 | 规避及验收边界 |
| --- | --- |
| 快路径把来源失败当无变化 | 每次身份/路径及前后签名检查；失败不确认版本；强制刷新和旧快照回归 |
| 两秒轮询的 job 文件也可能持续变化 | job stat 改变就失效并重新核验；本次不宣称所有活跃轮次都能快返。分别测静态来源与追加/修订，界面仍须可操作 |
| >2MB 缺少最新全文的跨进程持久兜底 | meta 只证明成功来源摘要，App 保留已加载全文；不提高上限、不冒充有完整快照 |
