# macOS 会话全文探针无采样对照施工计划

## 概要

- 问题：T0' 与 TX1 中，每个进程都开启采样器（10 ms 计时器与 5 ms 看门狗）。采样器是否为冷启动停顿的触发因素没有检验，TX1 的限制已写明这一点。
- 目标：去掉裸对照的采样器，其余与 T0' 相同（x 文本、65 537 字节、附着模式、作业结构）。产品对照保持采样器开启，作为同一运行中的阳性对照。两个方向的结论都可能出现。
- 依据：T0' 结果（运行 `40658656345`）：裸冷启动 3/3 停顿，产品冷启动有效 2/3（有效的是 attempt 4 与 6）。TX1 结果（运行 `40673713768`）：文本形状不是触发因素。
- 不做：不改产品源码；不改门禁与 publish；不放宽 250 ms；不改 max latency 指标；不在本地编译；不合并诊断分支；不对产品路径做无采样对照（见「限制」）。
- 状态：计划已写入，未提交、未派发。规则在派发前提交（提交需批准）。

## 停顿的定义

- 有采样的产品对照（阳性对照）：沿用 T0'，看门狗载入停顿 ≥ 200 ms，且 绘制到 locate ≥ 200 ms。
- 无采样的裸对照：区间 = `bare_attach` 的 `t_ms` 到 `bare_locate` 的 `t_ms`（定位结束）。区间 ≥ 200 ms 为停顿。
- 代理的依据：T0' 中三个裸冷启动进程（采样开启，有看门狗）的区间与看门狗停顿相差很小：

| T0' 裸冷启动 | 区间（附着到定位结束） | 看门狗载入停顿 | 差 |
|---|---|---|---|
| attempt 1 | 377.4 ms | 381 ms | 3.6 ms |
| attempt 3 | 504.3 ms | 503 ms | 1.3 ms |
| attempt 5 | 645.8 ms | 647 ms | 1.2 ms |

## 判读（派发前写入）

1. 结构检查与进程检查（先于一切）：每个作业必须恰有 6 份报告，日志中无 `FAIL:` 行，且无 JSON 错误；变体顺序必须符合 attempt 的奇偶（奇数裸先，偶数产品先）；每份报告的 `mode` 与变体一致（裸 `bare-attach`，产品 `attach`），字节数为 65 537。回显必须给出该变体的采样状态（裸 `off`，产品 `on`），报告必须与之一致：裸报告的 `probe_samples` 为 0 且无 `main_thread_ticks`；产品报告两者都非空。任一项不符，整轮不作结论。
2. 有效性（T0' 规则，不变）：产品冷启动 3 个中至少 2 个同时满足看门狗载入停顿 ≥ 200 ms 与 绘制到 locate ≥ 200 ms。否则作废。
3. 裸冷启动判读（仅在第 1、2 条通过时）：B = 裸冷启动 3 个中区间 ≥ 200 ms 的个数。
   - B ≥ 2：采样不是裸对照停顿的必要条件。运行器环境（H4）候选保留。
   - B = 0：采样是裸对照停顿的触发因素（探针夹具类）。阳性对照在同一运行中停顿，所以不是本次运行整体没有停顿。
   - B = 1：不确定，不下结论。
4. 描述性数据（不进入判读）：裸热态与 after-other 的区间，作为无采样基线。

- 无采样报告中的 `result: PASS` 与 `probe_max_ms: 0` 没有意义，不得引用。

## 限制

- 「采样器」仅指 10 ms 计时器与 5 ms 看门狗。`wait` 中每 10 ms 的主 actor 轮询在两个变体中都存在（裸对照的附着之前；产品的安装之前，附着后最多一次）。结论不涵盖它。
- `bare_attach` 在 `scroll.documentView = view` 之后记录，因此该赋值不在区间内。T0' 的裸冷启动区间与看门狗停顿一致，说明那些运行中的停顿位于区间内；无采样时无法再次检查。
- 余量：T0' 中裸非冷启动区间最大为 146.8 ms，阈值为 200 ms。区间的非冷启动余量只有约 50 ms，比看门狗弱。
- 范围：产品对照本轮保持采样开启。若 B ≥ 2，结论只涉及裸对照，产品路径的无采样停顿仍未检验，结论不扩展到产品路径。
- 样本量：每组 3 个进程。
- 若作废（产品阳性对照未达到有效性）：不能区分「采样是必要条件」与「本次运行没有出现停顿」。需要另立计划，例如增加同一运行中的采样开启裸冷启动参照。
