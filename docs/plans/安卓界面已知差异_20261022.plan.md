## 方案

### 一、执行方式（需用户决定）

- 写成施工计划，由用户执行（推荐；按项目约定，本次不改代码）。
- 直接改代码，未提交，不构建、不安装。
- 改代码并构建、跑单元测试，未提交，不安装。

### 二、离线图标（差异 1–3）

推荐：实现补齐，复用现有矢量，不新增依赖。

- 连接行：离线时用 16dp 的 `ic_status_failed`（tint 为 `colors.error`）替代 8dp 圆点（`ConsoleUi.kt:101–104`）。在线绿点与「正在读取…」灰点不变。
- 横幅：`Banner` 增加可选图标参数（20dp，tint 跟随 `content`）。`ConsoleUi.kt:52` 的离线横幅传 `ic_status_failed`；`:54` 的结果待核实横幅传 `ic_status_alert`；`:56` 的通知不加图标。
- 契约 `:128–129` 与计划导航观察第 7 项、实施记录第 12 项同步。

备选：画布去掉两处图标，连接行改为 8px 红点（与画布在线绿点同构）；代码不改。代价是离线只靠颜色与文字区分，少一层图标识别。

### 三、离线说明文字（差异 4）

推荐：画布删去「断线时的规则」卡，并把「自动推进」描述与需要你条目的离线提示删去。理由：规则已由写操作门控与草稿保留实现，并写在契约 `:90`；画布卡片重复说明，而实现没有对应界面。

备选：实现补上说明卡与离线提示，并同步契约（新增 UI 文案）。

### 四、「正在读取…」（差异 5）

默认：画布补一个顶栏变体（8px 灰点加「正在读取…」，与实现同形），代码不改。备选：只留契约，不改画布。此项影响小，不单独询问。

### 五、需要你列表的 failed 项（差异 6，数据缺口）

推荐：本次只记入计划，不改协议。原因：这需要改冻结字段（`docs/protocol.md` §5.27.3），并同步核心投影与 Mac 端解析，属于规格先行的改动。

若现在做，顺序如下：

1. `docs/protocol.md` §5.27.3 增加异常严重度字段，名称与任务视图的 `exception.severity` 对齐；契约 `:121` 同步。
2. `core/kanpilot/engine/attention.py`：`build_item` 从 `derive.task_exception` 取值，不另写表；更新冻结字段元组（约 `:101–106`）及对应快照合同测试。
3. 核对 macOS 端解析 attention 条目时对未知字段的容忍（未核实）。
4. Android：`StatusStyle.kt` 的 `attentionStatusStyle` 读取该字段，failed 映射为「失败」（红）；补 JVM 测试。
