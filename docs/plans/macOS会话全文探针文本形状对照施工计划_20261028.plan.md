# macOS 会话全文探针文本形状对照施工计划

## 概要

- 问题：阶段二 C、最小文本对照、T0 与 T0' 的附着模式运行都使用同一种夹具文本：`x` 重复后接 `TAILNEEDLE`，无空格、无换行、没有断行机会（`b5c583b`、`7005b93`、`0773be2` 中的 `let single = String(repeating: "x", count: tailLocation) + tailMarker`）。夹具类别因此没有排除。
- 目标：检验冷启动停顿是否依赖文本形状。在裸对照与产品后台路径上换用含空格与换行的自然英文文本，其余条件与 T0' 相同。
- 依据：产品计划 `macOS会话全文后台路径首次停顿归因施工计划_20261028.plan.md` 的「T0' 结果」（整轮运行 `40658656345`）。该结果的「运行器环境」判读只在 `x` 文本下成立。
- 不做：不改产品源码；不改门禁与 publish；不放宽 250 ms；不改指标；不在本地编译；不合并诊断分支。
- 状态：计划已写入，未执行。提交与运行需你批准。

## 步骤

### TX1 文本形状对照（只改夹具）

- 诊断分支 `diag/session-fulltext-stall-20261028`，基于 `0773be2`。只改两处：
  - `macos/tests/session_fulltext_main.swift`：附着模式的 `single` 文本。若环境变量 `KANPILOT_PROBE_TEXT=natural`，文本由固定的 ASCII 英文段落拼接，段落之间与段落内每约 80 个字符插入一个换行，长度恰好为 `KANPILOT_PROBE_BYTES` 个字节（ASCII，字节数与 UTF-16 长度相同），末尾保留 `TAILNEEDLE`，高亮位置不变。缺省仍为 `x` 文本。
  - `macos/tests/run-session-fulltext-fixtures.sh`：附着运行加 `KANPILOT_PROBE_TEXT=natural`，其余不变。
- 作业结构与 T0' 相同：attempt 1–6，奇数 attempt 裸先跑，偶数 attempt 产品先跑，每段 3 个进程，尺寸 65 537 字节。冷启动为作业的进程 1。
- 分组：裸对照自然文本冷启动（奇数 attempt 的进程 1，3 个）；产品自然文本冷启动（偶数 attempt 的进程 1，3 个）；其余为另一变体之后的进程或热态。
- 有效性（派发前写入）：产品自然文本冷启动 3 个中至少 2 个同时满足绘制到 locate ≥ 200 ms 且有载入停顿（与 T0' 相同）。否则本对照作废，不下结论。
- 判读（派发前写入，仅在有效时适用）：
  - 裸对照自然文本冷启动 ≥2/3 停顿：文本形状不是触发因素。两种文本在同一运行器上都停顿，运行器环境（H4）候选保留。
  - 裸对照自然文本冷启动 0/3 停顿：`x` 文本的形状是触发因素。停顿归入探针夹具的文本，不归入产品代码或运行器。
  - 1/3：不确定，不下结论。
- 停顿判定与 T0' 相同：载入 episode ≥ 200 ms；看门狗持续采样到停顿结束。
- 成本：一次整轮运行加 5 次探针重跑。

## 限制

- 只换一种自然英文段落，不穷尽文本形状（中文、长词、代码块、Markdown 未测）。
- 产品自然文本的有效性沿用 T0' 的门槛；若无效，本对照没有结论。
- 运行器之间的冷启动差异大（T0' 中产品冷启动为 254–637 ms），每组只有 3 个进程，统计力度有限。
- 本对照不能识别具体的系统资源。
- 实现只增加一个环境变量分支，编译在云端执行（AGENTS.md）。若编译失败，记录原因并修正，不计入对照结果。
