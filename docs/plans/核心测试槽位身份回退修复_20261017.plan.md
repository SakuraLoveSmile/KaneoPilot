# 核心测试槽位身份回退修复

## 概要

核心套件（`core/tests`）有 9 个失败，全部集中在 `tests/test_cli_review.py`（8 个）和 `tests/test_claude_cli.py`（1 个）。它们在合并前的 `7102a60` 上同样失败，报错一致，不是本次合并引入的。

根因是 `7102a60` 把 `core/tests/test_cli_review.py` 还原成了 `11f0da2`（`13713b9` 之前）的版本，而 `13713b9` 为评审槽位引入的身份校验仍保留在生产代码里。测试夹具因此不再写入校验所需的请求行。

修复只需恢复一个测试文件，不改生产代码。

本计划只定方案，不改代码、不构建、不安装、不写库、不提交。

状态：待执行（2026-10-17）。

## 证据（只读）

- 核心套件（`core/tests`，隔离环境变量）：`2991 passed, 688 subtests passed, 9 failed`，耗时 2780s，退出码 1。失败用例：
  - `tests/test_claude_cli.py::test_invalid_settings_env_settles_review_without_launch`
  - `tests/test_cli_review.py::test_run_stage_records_cost_before_settlement`，参数 `[False-claude]`、`[False-codex]`、`[True-claude]`、`[True-codex]`（4 个）
  - `tests/test_cli_review.py::test_cli_branch_review_shares_artifact_guard`，参数同上（4 个）
- 根目录套件（`tests`，含 rehearsal）：`396 passed, 5 skipped, 4 subtests passed`，退出码 0。
- 合并前基线 `7102a60`（`git archive` 导出到 scratchpad，隔离运行）：同样 9 个失败，报错相同。
- 清空所有 `CLAUDE*` 环境变量（`env -i`）后，在 `e8dc34f` 上仍然失败，排除 Claude Code 会话环境变量。
- 报错信息：`executor review Plus 控制轮受阻：槽位请求身份已变化`，打印于 `core/kanpilot/pi_desktop_review.py:950`。
- 诊断（scratch 副本，未改仓库）：`e8dc34f` 中把 `core/tests/test_cli_review.py` 换成 `13713b9` 的版本后，`test_claude_cli.py` 与 `test_cli_review.py` 共 `40 passed, 13 subtests passed`。

## 根因

1. `13713b9`（feat: bound planning and review worktrees with leased slots）为评审引入槽位身份校验：
   - `core/kanpilot/task_workspace.py:288` 的 `acquire_pool` 调用 `db.get_request(conn, request_id)`，读取真实数据库中的 `requests` 行，要求 `status == "claimed"` 且 `run_id` 一致，否则在第 298 行抛出 `槽位请求身份已变化`。
   - `core/kanpilot/pi_desktop_review.py:309` 在准备评审工作树时调用它。
2. 同一提交更新了 `core/tests/test_cli_review.py`：`runner_scene` 向真实库写入 `req1` 请求行，`core_call` 的 `report` 分支同步更新它；`test_run_stage_records_cost_before_settlement` 断言评审工作树目录以 `slot-` 开头。
3. `7102a60`（feat: integrate Plus verification, terminal recovery and execution question UI）没有修改任何槽位代码，但把 `core/tests/test_cli_review.py` 还原成了 `11f0da2` 版本：
   - `git diff --stat 11f0da2 7102a60 -- core/tests/test_cli_review.py` 为空，两者字节一致。
   - `git diff 13713b9 7102a60 -- core/tests/test_cli_review.py` 显示：请求行插入、`update_request` 调用、`slot-` 断言都被删除，断言改回 `review-`。
4. 结果：夹具不再写入请求行，生产校验（保留）在 `acquire_pool` 处报冲突，测试全部在评审开始前失败。
5. `test_claude_cli.py` 不是独立原因：它通过 `from test_cli_review import runner_scene`（第 11 行）复用同一夹具。它与 `13713b9` 版本一致（`git diff 13713b9 7102a60 -- core/tests/test_claude_cli.py` 为空），其 `run_stage` 调用（第 286 行）已使用 `tmp_path / "isolated.db"`。
6. `slot-` 命名与现行代码一致：`core/kanpilot/worktree_pool.py:214–216` 生成 `slot-N` 路径。`7102a60` 的 `review-` 断言已过时。

## 修复方案（待执行）

1. 恢复测试文件（该命令会把改动放入暂存区，执行后按需取消暂存）：

   ```bash
   git checkout 13713b9 -- core/tests/test_cli_review.py
   ```

   这会覆盖 `7102a60` 对该文件的全部改动，实际差异只在上面第 2 点列出的三处。
2. 不改 `core/tests/test_claude_cli.py`（已与 `13713b9` 一致，无需改动）。
3. 不改生产代码。若认为评审工作树不应使用 `slot-` 命名，或应放宽身份校验，需先修改规格（`docs/protocol.md`），再另起计划。
