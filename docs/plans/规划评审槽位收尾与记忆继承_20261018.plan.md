## 缺口与方案

### G1 Plus 路径记忆（M4）：代码已安装，待金丝雀验证

- 机制：Plus 读取登记投影 `~/Library/Application Support/KaneoPilot/worktree-slots.json`（PI-Desktop `crates/host-core/src/project_memory_owner.rs:39-44`），把槽位解析为真实仓库的记忆归属。投影由核心写出（`core/kanpilot/worktree_pool.py:98-107`），规格见 `docs/protocol.md` §5.29.4（第 1675–1677 行）。
- 缺的是实测：没有真实模型运行，也没有在真实仓库上验证过记忆注入。
- 方案（不改代码）：
  1. 用户在 Plus 中为 Music 建立项目行（当前不存在），写入一条金丝雀记忆（测试内容，验证后删除）。Plus 界面是否允许对无会话的仓库写记忆，见 U1。
  2. 发起一次 Music 规划。规划会调用模型，需要你单独授权（L3）。
  3. 核对会话启动载荷（不是模型输出）：包含金丝雀；cwd 为槽位；真实仓库不作为 Primary root 出现（§5.24.3-1）。
- 验收：A2。

### G2 CLI 路径记忆（Claude / Codex）：未覆盖

- 机制：规划与评审的 cwd 是槽位（`core/kanpilot/planner_runner.py:760`、`core/kanpilot/claude_planner.py:97`、`core/kanpilot/cli_review.py:201`、`:260`、`:263`）。Claude Code 的自动记忆按 cwd 编码后的目录读取（`~/.claude/projects/<编码路径>/memory`），槽位没有对应目录。这是 Claude Code 的既有行为，本次未在运行中核实（U2）。
- 当前影响：`planner_config` 与 `review_config` 为 `pi_desktop`，CLI 路径不在默认流程中。
- 方案选项：
  - A（推荐，若将来启用 CLI 后端）：核心在组装规划与评审提示词时，只读注入真实仓库记忆目录的 `MEMORY.md` 索引（限长，注明来源）。细节文件的只读访问方式待验证（U2）。
  - B：为槽位建立指向真实记忆目录的符号链接。不推荐：会话写入可能穿透到真实记忆，且需要生命周期清理。
  - C：不处理，在文档中声明限制。

### G3 Plus 侧边栏的 `slot-N` 行：PI-Desktop 另起计划

- 机制：`ensure_project`（`crates/host-core/src/db/repositories.rs:312`）按路径建行，名称取目录名；`list_projects`（`:363`）无过滤。
- 方案：PI-Desktop 在列表展示层隐藏路径位于 `<worktrees_root>/pool/` 下的项目行，会话保留。禁止删除既有行，也禁止调用 `projects.remove`（`crates/host-core/src/rpc/mod.rs:2198`，会批量删除该项目的会话）。
- 已有行 `slot-1`（id 55）：本计划不删除。隐藏生效后保留；如需删除，由你逐项确认。

### G4 历史目录清理：需要“人工确认 + 归档优先”路径

- 机制：`worktree-audit` 与 `worktree-gc` 已注册（`core/kanpilot/cli.py:34-36`），实现见 `core/kanpilot/cmd_worktree.py` 的 `_audit`（378）、`_retention`（642）、`cmd_worktree_audit`（649）、`cmd_worktree_gc`（668）。守卫按设计保守，当前 0 候选。
- 原因：旧 Plus 会话没有可证明的终态回执（43 条），多数目录仍有未提交改动（37 条）或仍在保留期内（40 条）。
- 方案：新增人工确认路径，不放宽自动守卫。
  1. 只读生成清单：每条含路径、分类、阻塞原因、脏改动摘要、分配大小、最后修改时间。
  2. 你逐条或每批（不超过 10 条）选择：保留、归档或删除。
  3. 归档优先：脏改动先写入恢复引用（如 `refs/archive/worktree-cleanup/<日期>/<id>`，指向保存未提交内容的提交，不改动当前分支）；未跟踪与被忽略的文件复制到 `KaneoPilot-archives/<日期>/`；写 SHA256 清单与 `runtime_operations` 回执。
  4. 删除只在归档核验通过后、并经你再次确认时执行：`git worktree remove`（不加 `--force`），随后 `git worktree prune`。
  5. 删除后核对 `git worktree list` 与磁盘目录双向一致。
- 不在本路径内：
  - `execution_branch`（18 条）按 AGENTS.md「分支合并后的清理」处理，须任务已合并。
  - `execution_or_state`（3 条，227.7 MiB，UUID 执行回退）按 B9 不池化，需另行定义任务生命周期的回收规则。
- 规格先行：`docs/protocol.md` §5.29.3（第 1669 行）需增补确认与归档步骤，再动代码。
