# Android 界面视觉与排版优化

## 概要

对象：Android 远程控制台（`android/app/src/main/java/com/sakurasep/kaneopilot/`）的总览、任务页、需要你卡片、任务详情概览、执行复盘、顶栏与状态徽标。要解决的问题与 Mac 一致：首屏被计数占满、状态词把多种原因并成一个词、泳道色对比度不足、问答表单太长。

姊妹计划：`docs/plans/Mac界面视觉与排版优化_20261025.plan.md`（Mac 端与设置页）。两份计划共用状态词、泳道色、时长写法三套规则；规格改动由 Mac 计划的 S0（`docs/ui-spec.md`）与本计划的 A0（`docs/mobile-console-contract.md`）同批提交（见变更清单）。

对照材料：设计画布（私有，仅作者可打开）https://claude.ai/artifact/DeJQQDPpkKegs3EspV2A1f 的 5 张安卓画板：安卓总览、安卓任务页、安卓任务详情、安卓执行复盘（含深色）、令牌 · 安卓泳道色与对比度；问题清单在「现状问题清单 · 安卓与设置页」，编号 E1–E7 与下文一致。「当前」画板由 Compose 代码还原，颜色取 `Theme.kt`、`ObserveTheme.kt` 的字面值，没有用 Roboto，也没有在设备上看过；「优化后」是示意稿，高度与首屏位置是在浏览器里量的估算（约 ±15%）。画板与本文有出入时以本文为准。

状态：用户已确认 7 项设计取舍（2026-10-25，见「已确认事项」）；其余按画布默认处理，列在「默认处理」里，开工前可一并否决。本文是新增文件；实施状态见文末「实施记录」，`docs/ui-spec.md` 不在本计划内改动。

## 目标形态

### 状态词与徽标

状态文字取核心 `exception.label`，不再把多种原因并成「需人工」「阻塞」。Mac 采用同一张词表（Mac 计划「状态词」一节），列表行与详情头部在两端都读行里的 `exception` 与 `execution_question`（Mac 的 `TaskSummary` 为此新增 `execution_question` 小结构，见其 S2 第 2 条），安卓列如下。图标与语气由 `severity` 和 `kind` 决定，不靠标签文字反查；`exception.label` 为空（旧核心）时回到现行兜底。

| 来源 | 文字 | 图标 / 语气 |
| --- | --- | --- |
| `severity == "failed"` | `exception.label`（规划失败、派发失败、执行失败、失败；label 为空时写「失败」） | Failed / 红 |
| `kind == "manual_block"`，`execution_question.state == "open"` 且 `answerable` | 等待你回答 | Alert / 橙 |
| 同上，`answerable == false`（需在 Plus 中回答） | 等待你在 Plus 中回答 | Alert / 橙 |
| `kind == "manual_block"` 其他 | 需人工处理 | Blocked / 橙 |
| `review_blocked` | 评审受阻 | Blocked / 橙 |
| `send_unknown` | 发送不明 | Blocked / 橙 |
| `observation_blocked` | 监控异常 | Blocked / 橙 |
| `review_rejected` | 待修复（与 Mac 一致，保持短写法） | Blocked / 橙 |
| `executor_lost` | 执行端失联 | Blocked / 红 |
| 其他 kind（`release_blocked`、`parent_closeout_blocked` 等，label 由核心动态给出） | `exception.label` | Blocked / 橙 |
| 无异常 | 沿用现表：开放提问 →「等待你回答」，其余按 `display_status` 映射 | 沿用 |

- 开放提问的判定从「异常之后」前移到「异常 kind 为 `manual_block` 之后、取 label 之前」：同一个任务不再先显示「需人工」再靠别处补一句「等待你回答」。已答复、已关闭的提问不改变状态，与现行一致。
- 「等待执行端接收」（答案已提交、Codex 尚未接收）安卓不增加，保持现状。
- 中性徽标的图标色由 `outline` 改 `onSurfaceVariant`（2.93:1 → 7.21:1 浅色，深色 3.47:1 → 5.48:1，均为字面值计算）。
- 需要你卡片的徽标：先看 `attentionAction`（可回答 →「等待你回答」，待确认执行 →「待确认执行」），其余用 `task_id` 在 `list-tasks` 结果里找同一任务并走 `taskStatusStyle`，找不到时写「需人工处理」。条目不带 `exception` 是核心现状（E8），所以总览与「需要你」页在有需要你条目时也读一次 `list-tasks`；这是本轮的默认做法，另一条路（让核心在条目里带 `exception`）见「默认处理」。
- 契约 `:129` 第 4 项写明：`list-tasks` 行的 `exception` 与 `attention` 在手机响应里保留，但只做过静态核对，真实库里没有非空样本。联合验收要用夹具走一遍（见「验证」）。

### 顶栏

- 列表页标题由「KaneoPilot」改为页面名：总览、任务、需要你、连接，第二行仍是连接状态；详情页不变（小字「任务详情」，大字任务标题，两行省略）。应用名只留在「连接」页底部的版本行。

### 总览

顺序：已暂停时的橙色横幅 →「需要你 · N」→「看板」→「自动推进」。

- 「需要你」提到最前，最多 8 张（现行 `take(8)`）。卡片：第一行徽标加「项目 · 等待 N 分钟」，第二行任务标题（titleMedium），第三行原因（bodyMedium，来自 `question_preview`、`failure_reason`、`blocked_summary`），最后是动作：可回答 →「打开回答」，待确认执行 →「查看计划」，其余写「该操作需在 Mac 上完成」。卡片结构与「需要你」页共用同一个组件（契约 `:173`）。
- 「任务总览」只保留「看板」一行徽标；「任务」「请求」两组折叠成一行「更多统计：任务状态 N 类 · 请求状态 N 类」（N 取返回的键数），点开才显示，状态用 `stateDescription` 报出。
- 「自动推进」卡移到页尾，「暂停自动推进」「恢复自动推进」由实心按钮改描边按钮；未连接时仍是禁用的描边按钮加「连接后查看状态」。
- 已暂停时在列表上方出横幅：「自动推进已暂停」，说明「运行中的会话继续执行。」，右侧文字按钮「恢复自动推进」；沿用 `Banner` 组件，`tertiaryContainer` 加 `ic_status_alert`，按钮的启用条件与页尾按钮相同。横幅只在总览页出现。
- 估算：优化后「需要你」3 张卡与「看板」一行都在首屏约 705dp 内（画板量取）。

### 任务页

- chips 改单行横向滚动：去掉 `:540` 的 `heightIn(min = 48.dp)`，视觉高 32dp，点击区由 Material 3 默认的最小交互尺寸保证 ≥48dp（不再手写撑高）。chip 行高约 40dp。
- 分组头：文字用 `onSurfaceVariant`，只有「需要你处理」前面加一个 8dp 的 `tertiary` 圆点；去掉红字。
- 行：扁平，去掉 `Card`，行间用 `outlineVariant` 分隔线，上下内边距 12dp，每条约 100dp（画板量取，现行 124–144dp）。第一行任务标题加右侧更新时间（`MM-dd HH:mm`，沿用 `RetroFormat.dayTime`）；第二行状态徽标（24dp，与全站同一个 `StatusChip`）加项目名；第三行原因，最多 2 行，不再加「阻塞：」「失败：」前缀（徽标已说明类别，否则「评审受阻」后面跟「阻塞：…」互相重复）。行首的 ▲ ● ✕ 全部删除。
- 估算：首屏约 705dp 放得下 5 条（现行 3 条）。
- 分组与顺序、chips 口径、`Observe.grouped` 都不变。

### 任务详情概览

有开放问答（`execution_question` 或 `plan_clarification`）时：

1. 状态行：徽标加「项目 · 已等待 N 分钟」。执行问题的等待秒数取核心 `execution_question.wait_seconds`，不用手机时钟；规划问题没有该字段，只写项目。
2. 标题行：执行问题为「回答 N 个问题」（titleMedium），右侧「已答 X/N」（labelMedium）；规划问题的标题仍是「规划待回答」（界面测试和契约都用这个名字），其余版式相同。
3. 每题：序号、标题、必答星号、「单选 / 多选」标记，其下说明（bodySmall）；选项收进圆角 12dp 的分组（`surface` 底，1dp `outlineVariant` 描边，行间分隔线，行高 ≥48dp）；选中行 `secondaryContainer` 底；单选用 `RadioButton`，多选用 `Checkbox`；带说明的选项占两行。
4. 「自定义回答」是分组里的最后一行：单选题选中该行才展开输入框（`OutlinedTextField`，`minLines = 2`）；多选题与规划题沿用现行规则（规划题仍须选中「自定义方案」才出现输入框）。题与题之间留 16dp，不用分隔线。
5. 「清除此题答案」画板没画（示例里第 1 题已答，真实界面会出现这个按钮），现行是每题末尾一行 48dp 的文字按钮。实施时放进该题标题行右侧（只在该题已有答案时出现，点击区仍 ≥48dp），不占独立一行。
6. 表单末尾：一行 bodySmall 提示（「还差第 N 题 · 断线后可继续填写草稿，恢复连接后再提交」；全部答完时只留后半句），其下并排两个按钮：描边「保存草稿到 Mac」，实心「提交答案」，各占一半，高 ≥48dp；不做悬浮底栏。按钮文字、启用条件、确认对话框都不变。
7. 表单之后是「任务信息」卡：项目、任务编号、更新于三行加原有的一句提示（「手机仅开放回答问题、确认执行；其他操作请在 Mac 处理。」）。
8. 没有开放问答时，状态行之后保留当前进度、等待原因、失败原因三行（「当前进度」与「等待原因」相同时只显示一行，契约 `:180`），再接「任务信息」卡。表单显示时，与问题预览重复的「等待原因」不再单列。
- 估算：画板里保存与提交按钮落在约 564–612dp（现行 1098–1202dp），首屏约 649dp。但画板没有「清除此题答案」：放进标题行会把该行从约 22dp 撑到 48dp（点击区 ≥48dp），按钮再下移约 26dp，落在约 590–638dp，离首屏底边只剩约 11dp；放在题末则下移约 48dp，落到首屏之外。余量都小于估算误差（±15%），所以「按钮在首屏内」不作为结论，只是设备核对项；画板说明里「首屏内可见」的说法以此为准。

### 执行复盘

- 标题行：「执行复盘」加右侧「已用时 N」；其下保留只读提示一句。
- 关键指标 4 项，两列两行：执行用时（附「不含等你处理」）、验证 X/Y（附「未核验 N 条」）、修复轮 N/M、等你处理（「N 次 合计 N 分钟」）。数值用 `titleLarge` 半粗，标签 labelMedium。「验证」原先是下方「验证与检查」块里的一行文字，提到指标里，块内保留验证执行统计一行。数据规则沿用现行：执行用时、等你处理没有数据写「未汇总」（`executionValue`、`waitingValue`），修复轮没有 `automation.fix_round` 时整项省略。
- 泳道：规划、派发、执行、等你处理、修复、评审六条，右侧写「N 分钟 · n%」，取代独立的「时间分布」块（删除 `Distribution`）。核心 `distribution` 含「其他」且秒数大于 0 时，在六条泳道之后追加一行文字「其他 N 分钟 · n%」（没有轨道），以保住「合计 100%」。门控关闭时「等你处理」泳道仍写「未汇总」。
- 泳道色按角色取 Material 3 `colorScheme`：`primary`（规划、派发、执行、修复）、`tertiary`（等你处理、评审）、`outline`（其他）。同色泳道靠行标签、位置和右侧的数字区分，不靠色相。空闲段的虚线样式保留。
- 对比度（字面值计算，泳道画在 `surfaceContainer` 上）：primary 浅 6.10 / 深 9.49，tertiary 5.87 / 9.59，outline 3.87 / 5.13，均不低于 3:1；令牌板有逐色明细。
- 「重点」「验证与检查」两块保留，数字改新时长写法。
- 删除 `ObserveTheme.kt` 与 `observeLanes()`，`ConsoleUi.kt` 里不再写十六进制。

### 时长写法

与 Mac 的 S8 同一张表：不足 1 分钟「N 秒」；1–59 分钟「N 分钟」（舍去不足 1 分钟的秒数）；1–23 小时「H 小时 M 分钟」（M 为 0 时省略）；24 小时及以上「D 天 H 小时」（H 为 0 时省略）。`RetroFormat.duration` 按此重写，函数名保留；复盘与卡片等待时间共用。

卡片的「等待 N 分钟」：需要你条目只有 `since`（`blocked_at`，缺失时回落 `updated_at`），没有核心算好的秒数，所以用手机当前时间减 `since`，下限 0，解析失败则整段省略。契约 `:115` 的「不以手机时钟相减」写在复盘一节，约束的是复盘时长；A0 在 `:115` 后补一句说明卡片等待时间只是显示提示。

## 风险

1. 需要你卡片的标签依赖 `list-tasks` 行里的 `exception`，而它在真实库里只做过静态核对（契约 `:129`）。读不到时卡片回落为「需人工处理」，不会出错，但会失去本轮要的区分。
2. 总览与「需要你」页多一次 `list-tasks`：每 5 秒轮询里多一次请求和一份较大的响应。只在有需要你条目时才取；若觉得代价过高，改走核心带 `exception` 的另一条路。
3. 云端既不编译也不运行 `androidTest` 源码，A7 的手工同步可能漏改而无人发现；至少要在设备联合验收时把这三个文件跑一遍。
4. 顶栏标题与底栏标签同名后，所有按文字取节点的界面测试都可能命中两个节点（见 A7）。
5. 估算数字（首屏条数、按钮落点）来自浏览器里的还原稿，约 ±15%；详情页按钮落点的余量不足 40dp（加上「清除」按钮后约 11dp，见「任务详情概览」），要在设备上核对。
6. 单行横向滚动的 chips 在窄屏只露出前 4 枚左右，后两枚（待评审、已完成）要滑动才可见。
7. 「保存草稿到 Mac」在 160dp 宽的半幅按钮里，字体放到 1.3 倍可能换行，按钮会变高。
8. 与 Mac 的措辞对齐依赖两份 S0 同批合入；只合一边会出现两端状态词、泳道色不一致。
9. 卡片等待时间使用手机时钟，手机与 Mac 时钟偏差会直接体现在数字里。
