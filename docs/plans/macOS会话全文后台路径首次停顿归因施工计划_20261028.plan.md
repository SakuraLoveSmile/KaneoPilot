# macOS 会话全文后台路径首次停顿归因施工计划

## 概要

- 问题：超过 64 KiB 的文本首次渲染时，主线程在同一运行器上阻塞 260–624 ms（阶段二 C 与 T0 合并）。T0 显示 64 KiB 的同步路径也在冷启动停顿，所以停顿不只属于后台路径。同一运行器上第一个大文本停顿，之后的大文本不停顿。
- 目标：把停顿归到具体的一段（同步安装，或首次绘制之后的等待），并判定它来自产品代码的挂接方式，还是系统层的首次加载。
- 不做：不改产品行为；不改门禁与 publish；不放宽 250 ms；不改指标；不在本地编译。产品源码改动只在诊断分支，且需你批准。
- 状态：T0 已执行（结果见「T0 结果」），路线 B 未得到支持。T0' 裸 AppKit 对照已执行（结果见「T0' 结果」，整轮运行 `40658656345`）：裸冷启动 3/3 停顿，判为系统层候选（H4）。T1 未批准，其前提未得到支持。依据：`macOS会话全文探针停顿调查施工计划_20261028.plan.md` 的「阶段二 C 对照：最小文本（已执行）」节（诊断提交 `b5c583b`，整轮运行 `40648669163`）。
- 实施前提：编译、签名与打包只在云端 Packages 工作流执行（AGENTS.md）；诊断分支不合并；新 worktree 放在 `$HOME/Documents/Code/Project/Project Worktree/KaneoPilot/<任务标识>/`。

## 已知事实

1. 停顿位置：`install`（`macos/KaneoPilot/Views/SessionMessageDetailView.swift` 第 495–517 行）开始至 locate 开始之间。locate 由 `applyHighlight`（第 519 行起）调度的主线程工作项执行。停顿约占该窗口的 85–96%。
2. 窗口内主线程在等待：CPU 占比 0.04–0.15（热态 0.26–0.72）。窗口内 page-in 为 40（1 MB 在 1 KB 之后的首次）与 84–91（冷启动 1 MB），热态为 0。
3. 后台路径的结构：`fulltext_prepare` 在后台队列完成（第 440–447 行）；主线程随后异步挂接（第 450–458 行）。挂接的是后台构建的存储与容器（`Prepared`），`makeTextView(size:container:)` 用它建视图（第 503 行）。
4. 同步路径（`prepare` 中 `text.utf8.count <= 64 * 1024` 分支）在主线程直接建视图，不经后台准备。1 KB 冷启动不停顿（0/3）。
5. 同作业规律：阶段二 C 中，每个作业的首个后台路径进程 6/6 停顿，同作业另一尺寸的后台路径进程 6/6 不停顿。最小文本对照中，热态 1 MB 0/12 停顿。
6. page-in 不能单独解释停顿：1 KB 冷启动的唯一可算窗口有 137 次 page-in，却没有停顿。
7. 混杂：1 KB 与 1 MB 同时改变了尺寸与路径。T0 已测 64 KiB 的同步路径：冷启动也停顿（见「T0 结果」）。
8. 裸 AppKit 对照（不含 SwiftUI 宿主与产品封装函数）在冷启动复现了同一窗口的停顿（3/3），见「T0' 结果」。

## 假设

- H1：同步段阻塞。候选为 `makeTextView`、`documentView` 赋值、`applyHighlight` 中的高亮与选择。（T0' 后：裸对照保留了这些调用，T0' 不能区分本假设；T0 的判读保持。）
- H2：首次绘制之后、locate 之前，主线程在 AppKit 内部等待（布局、字形或资源的首次加载）。
- H3：挂接方式的代价。后台构建的存储与容器在主线程首次使用时才完成必要的工作。这是产品设计问题，对应路线 B。（T0 后：同步路径在 64 KiB 冷启动也停顿，本假设不被支持。）
- H4：系统层首次加载（字体、TextKit 的大文本路径）。1 KB 冷启动使用同一字体与 TextKit 却不停顿，因此 H4 单独不足以解释，但仍需验证。（T0 后：与「同一运行器上第一个大文本」的模式一致，未验证。T0' 后：裸 AppKit 复现冷启动停顿，成为候选；具体系统资源未识别。）

## 限制

- 埋点本身有开销。诊断结论只用于定位，不作为性能数字。
- 每组只有 3 个进程，统计力度有限。
- 1 KB 与 1 MB 的尺寸与路径混杂。T0 之后，路径已不能解释停顿（同步 64 KiB 也停顿），但尺寸与系统因素仍未分开。
- 裸对照未照抄的差异：产品视图经 SwiftUI 宿主挂接（宿主覆盖 `setFrameSize` 与 `layout`），裸对照没有这一层；产品封装代码（`install`、`applyHighlight` 的代次与取消）未照抄；后台准备队列 QoS 不同（产品 `.userInitiated`，裸对照默认）。这些差异的影响未检验。
- 所有停顿运行使用同一夹具文本（65 537 个 `x`，无空格、无换行、没有断行机会）。文本形状未变，夹具类别不能排除为触发因素。运行器环境的判读依赖 T0 的「同一作业内第一个大文本」规律（跨进程保留）；T0' 只表明这一规律在去掉 SwiftUI 宿主与封装代码后仍然复现。
- CI 运行器上的冷启动停顿不代表用户的 Mac。本结论只适用于 GitHub 托管运行器上的探针。
