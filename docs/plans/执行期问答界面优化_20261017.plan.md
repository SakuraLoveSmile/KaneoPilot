## 现状与根因（锚定 HEAD `bf28b07`）

**根因 1：已关闭记录按当前问题渲染。**
- `TaskOverviewTabView` 以 `detail.executionQuestion` 渲染 `ExecutionAnswerCard`（`macos/KaneoPilot/Views/TaskDetailContentView.swift:793–794`）。protocol §5.28.2 规定：没有开放请求时返回当前 run 最近的关闭记录。UI 没有按 `state` 分流。
- 标题写死「执行中提问 · N题」（:1313），副标题写「已等待」（:1315）。对 answered、expired、stopped 都不是事实。

**根因 2：关闭记录仍是整张表单。**
- `ExecutionAnswerStore.inputsLocked`（`macos/KaneoPilot/AppViewModel.swift:2015`）在 `state != "open"` 时锁定输入，选项与「跳过此题」变灰。看起来像可操作，实际不可操作。
- 卡片背景为 `Color.orange.opacity(0.12)`（:1425）。ui-spec §4.17 第 483 行写明「不增加独立大卡片、阴影或全局皮肤」，§3 要求颜色只用系统语义色。

**根因 3：底栏主动作与问答脱节。**
- 有开放请求时，`core/kanpilot/derive.py:533` 只返回 `answer_execution_questions / skip_execution_questions / stop_execution`。底栏主按钮是「回答执行问题」（:1076），它只滚动到卡片，不提交。
- 无开放请求时（截图状态），主按钮退回通用「安排下一步」（:1144）。
- 「提交答案并继续」位于卡片最底部（:1410），两题以上要滚动才能看到。禁用时（`canSubmit`，`AppViewModel.swift:2019`）不说明还缺哪一题。

**根因 4：概览信息重复。**
- 同一件事在三处表达：头部状态徽标「执行中」与「阶段：执行」（`TaskDetailContentView.swift:101–109`）、阶段步进下方的「阶段：执行 · 条件：执行中」（`Components.swift:782` 的 `PhaseStepperView`，调用于 `TaskDetailContentView.swift:781`）、「状态与推进」里的「当前状态 / 生命周期阶段 / 最后更新」（:927–946）。

- 头部标题在非执行页只允许一行（:95），截图中的长标题因此被截断。

**需要实机确认的张力（不是已确认的结论）**
- §4.17 第 483 行要求执行问答的 label 支持选择文本，因此执行卡片的选项文字带有 `.textSelection(.enabled)`（:1475）。规划问答的 optionButton（HEAD `TaskDetailContentView.swift:325–347`）没有这一设置，而 §4.17 第 485 行又要求选项「继承既有 optionButton 形态」。
- 假设：可选文本可能拦截按钮点击，导致点文字不选中。需要在实机上分别点击选项文字与行内空白来验证。若证实，须先修改规格（例如仅题目与说明可选，选项 label 不可选），再改代码。

## 目标形态

### A. 按状态分流问答区

数据只来自核心 DTO（`state`、`delivery`、`answerable`、`answered_by`、`closed_at`、`submitted`、`draft`），Swift 不另造状态。

| 核心状态 | 呈现 |
| --- | --- |
| `open` 且 `answerable` | 完整问答。标题「等待你回答 · N 题」（18pt semibold）；元信息一行「Plus 执行会话 · 已等待 N 分钟 · 已答 X/N」（11pt）；选项沿用规划问答的 optionButton 形态；去掉橙色底，题目之间用 Divider 分隔 |
| `answered` | 一行摘要：answered_by=kaneopilot 显示「已回答，继续执行」，plus 显示「已在 Plus 回答」，unknown 显示「问题已回答，回答来源未知」（按 §4.17 第 493 行，不冒充某端作答）。附 closed_at 的本地时间，并提供「查看回答」，展开后是只读列表（每题所选项、自定义文字或「已跳过」） |
| `expired` / `stopped` | 一行原因（核心 detail 或 failure_reason）+「查看问题与草稿」只读展开。后续操作仍由核心 `execution_failed` 决定（§4.17 第 494 行既有规则） |
| `answerable=false` | 保留「请在 Plus 中回答」与核心原因，关闭本地输入 |
| `submitting` / `unknown` / 观察中断 | 只在对应状态出现现有状态文字与「重新核对」「重新连接」，其余时间不占位 |

### B. 提交动作上移到底栏（需改规格）

- 开放时，底栏主按钮为「提交答案」，标注进度。未答完时禁用，并写明「还差第 N 题」；提交中显示进度；unknown 时改为「重新核对」（沿用 §4.17 第 488 行规则）。
- 「保存草稿」「全部跳过并继续」「停止本轮」移入「更多操作」，沿用现有确认对话框。§4.17 第 490 行原文是「下方低频动作」，因此需要改规格。
- 底栏不再出现只滚动的「回答执行问题」按钮。
- 无开放请求时，底栏完全按核心 `allowed_actions` 工作，不改核心，不在 Swift 中过滤或补写动作。
- 底栏与卡片必须使用同一个 `ExecutionAnswerStore`（经 `model.executionAnswerStore`，`AppViewModel.swift:883`），不得各自新建。确认对话框的状态从 `ExecutionAnswerCard` 提升到 `TaskOverviewTabView`。

### C. 头部状态

开放提问时，头部状态徽标显示「等待你回答」（图标 + 文字）。只改头部展示（`headerStatus`，`TaskDetailContentView.swift:101`），不改 `DisplayStatus.effective` 的既有派生，避免影响其他列表与徽标。

### D. 选项与标题

- 选项文字的可选择性按 E 类实机结论处理（见上文「需要实机确认的张力」）。可复制的需求由卡片的「复制原答案」承担，只在有草稿时出现。
- 概览页标题允许两行，与执行页一致（`TaskDetailContentView.swift:95` 的 `lineLimit` 条件改为两行）。

### E. 概览精简（可选，超出 §4.17 范围）

- 去掉与头部重复的「当前状态 / 生命周期阶段 / 最后更新」行，保留一句「下一步说明」。
- 阶段步进的「条件」文字不再重复，头部只保留一处阶段信息。
- 「阶段入口」改为紧凑链接行，或并入分段页签。

此项会改动 §4.1（概览的状态行与阶段入口）与 §4.12 的既有表述，需要单独批准，并先改规格。
