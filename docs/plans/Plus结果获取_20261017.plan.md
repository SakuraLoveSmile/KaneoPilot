## 2. 新口径

完成判定只看 Plus 的报告，Pilot 不回查转录。

1. 身份：task、run、turn 与 `plan_sha256` 相符。报告经 `cmd_read.read_goal_report` 做身份核对（`core/kanpilot/cmd_read.py:1065`，已有）。
2. 报告底线：`state=ready`、`integrity=structured`、`execution=completed`、`verdict=met`。沿用 `verify_goal_completion`（`cmd_read.py:1317`）的前四项，但不要求 monitor AI 的审查项 `reviews`。
3. 覆盖：每条冻结 verify 命令，规范化后（去行内 `VAR=value` 前缀、去尾部中文注释、去首尾空白）精确等于某条检查的命令，且该检查 `exitCode=0`、`result=passed`。缺一条即未通过。
4. 空 diff 规则不变：有效 diff 排除 `.pi/**` 与交付构建产物，必须非空。
5. 分类：
   - 报告不可用（`not_found` / `pending` / `draft` / `failed` / `corrupt` / `truncated`）或覆盖缺失 → `unconfirmed`，不触发质量修复。
   - 检查真实非零退出且 `result=failed` → 质量失败，沿用既有语义。

代价：退出码是 Plus 自报的，Pilot 无法用工具结果交叉验证。Pilot 仍核对身份与报告哈希。

撤回的约束：执行端不再需要预设 `JAVA_HOME` / `ANDROID_HOME` / `PATH`。本次报告显示 Plus 用行内环境变量已经跑通。“禁止环境前缀、管道、后台”等限制只为转录匹配服务，随之撤回。
